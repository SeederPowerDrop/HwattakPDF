# 0장 코드를 처음 읽는 사람을 위한 준비

이 장은 코드를 한 번도 써 보지 않은 독자를 위한 출발점입니다. 목표는 PDF 앱 전체를 이해하는 것이 아니라, **“현재 3쪽에서 다음 쪽으로 이동한다”는 동작을 짧은 코드로 읽는 것**입니다. 지금은 설치나 실행 없이 종이에 결과를 적으며 공부해도 충분합니다.

이 장의 Swift 코드는 모두 **학습용 모형**입니다. 실제 앱에서 가져온 코드는 아니며, PDF 파일이나 화면을 바꾸지 않습니다. 각 `swift` 코드 블록은 서로 독립된 완전한 예제입니다. 앞의 예제를 실행하지 않아도 읽을 수 있고, 한 예제의 이름을 다음 예제에서 다시 써도 괜찮습니다. 결과 상자에 있는 글은 코드에 덧붙이지 않습니다.

## 0.1 프로그램은 무엇일까요?

프로그램(program)은 컴퓨터가 수행할 일을 정해 놓은 것입니다. 프로그래밍(programming)은 그 일을 작은 단계로 나누고, 컴퓨터가 이해할 수 있는 규칙에 맞춰 적는 작업입니다. Swift와 Rust는 그 규칙을 갖춘 프로그래밍 언어(programming language)입니다.

우리 앱에서는 “다음 쪽으로 이동하기”를 다음처럼 나눌 수 있습니다.

1. 지금 몇 쪽을 보고 있는지 확인합니다.
2. 아직 마지막 쪽이 아니라면 쪽 번호를 하나 늘립니다.
3. 바뀐 번호에 해당하는 PDF 페이지를 화면에 보여 줍니다.

사람에게는 당연해 보이는 “마지막 쪽을 넘어가지 않는다”는 규칙도 코드로 알려 주어야 합니다. 이처럼 문제를 작은 단계로 나누는 것이 문법을 외우는 것보다 먼저입니다.

앱(app)은 사용자가 실행해서 이용하는 프로그램입니다. 소스 코드(source code)는 사람이 읽고 수정하는 프로그램의 글이고, 소스 파일(source file)은 그 글을 담은 파일입니다. 예를 들어 이름이 `.swift`로 끝나는 파일에는 Swift 코드를 적습니다. 폴더(folder)는 관련 파일을 모아 두는 곳입니다. 앱 하나가 파일 하나로만 이루어질 필요는 없습니다.

## 0.2 가장 짧은 코드부터 읽습니다

`print`는 값을 결과 창에 표시하는 함수(function)입니다. 함수는 이름을 붙여 두고 필요할 때 사용하는 동작입니다. `print(...)`처럼 이름 뒤에 괄호를 붙여 사용하는 것을 호출(call)이라고 합니다. 먼저 결과를 표시하는 도구 정도로 생각해도 됩니다.

```swift
print("PDF 공부를 시작합니다")
print(3)
print(3 + 1)
```

예상 결과:

```text
PDF 공부를 시작합니다
3
4
```

첫 줄은 따옴표 안의 글을 표시합니다. 둘째 줄은 숫자 `3`을 표시합니다. 셋째 줄은 `3 + 1`을 먼저 계산한 뒤 `4`를 표시합니다. 따옴표는 글의 시작과 끝을 나타내는 코드 기호이므로 결과에는 보이지 않습니다.

이 예제는 위에서 아래로 실행됩니다. 다만 **소스 파일에 적힌 모든 코드가 언제나 처음부터 끝까지 바로 실행되는 것은 아닙니다.** 뒤에서 만들 함수의 내부는 함수를 호출할 때 실행됩니다. 실제 앱도 버튼을 누르는 등의 사건이 생기면 그 사건에 연결된 코드를 실행합니다.

**작은 연습:** 마지막 줄을 `print(3 + 2)`로 바꾸면 무엇이 표시될까요? **해설:** `5`입니다. 앞의 두 줄은 그대로입니다.

## 0.3 값에 이름을 붙입니다

값(value)은 프로그램이 다루는 구체적인 내용입니다. `3`이나 `"공부.pdf"`가 값입니다. 변수(variable)는 값을 보관할 때 사용하는 이름입니다. Swift의 `var`는 나중에 값을 바꿀 수 있는 이름을 만듭니다.

```swift
var currentPage = 3
currentPage = currentPage + 1
print(currentPage)
```

예상 결과는 `4`입니다. 첫 줄은 “현재 쪽”이라는 뜻의 이름 `currentPage`에 `3`을 넣습니다. 둘째 줄은 **오른쪽을 먼저 계산**합니다. 기존 값 `3`에 `1`을 더한 `4`를 왼쪽 이름에 다시 넣습니다. 셋째 줄은 그 값을 표시합니다.

`=`는 대입(assignment), 즉 오른쪽 값을 왼쪽에 넣는 기호입니다. 수학의 “양쪽이 같다”와 역할이 다릅니다. 그래서 `currentPage = currentPage + 1`은 모순이 아니라 값을 갱신하는 명령입니다.

`let`은 한 번 정한 뒤 다른 값을 대입할 수 없는 이름을 만듭니다. 이런 이름을 상수(constant)라고 합니다. 다음 예제의 전체 쪽 수는 실행 중 바꾸지 않으므로 `let`을 씁니다.

```swift
let pageCount = 10
var currentPage = 3
print(pageCount)
print(currentPage)
```

예상 결과는 첫 줄에 `10`, 다음 줄에 `3`입니다. 코드의 첫째 줄은 전체 쪽 수를 정하고, 둘째 줄은 현재 쪽 번호를 정합니다. 셋째·넷째 줄은 각각의 값을 표시합니다. 예제에서 쓰는 이름은 사람이 정한 것이며, 영어라는 이유만으로 특별한 기능이 생기지는 않습니다.

**작은 연습:** 이 예제의 둘째 줄을 `var currentPage = 7`로 바꾸면 전체 쪽 수도 바뀔까요? **해설:** 아닙니다. `pageCount`와 `currentPage`는 서로 다른 이름입니다. 결과는 `10`, `7`입니다.

## 0.4 숫자와 글은 다른 종류입니다

타입(type)은 값의 종류와 가능한 계산을 정하는 기준입니다. 처음에는 다음 네 가지만 알아도 충분합니다.

| Swift 타입 | 다루는 값 | 우리 앱에서 떠올릴 예 |
| --- | --- | --- |
| `Int` | 정수(integer): 소수 부분이 없는 수 | 현재 쪽 번호 `3` |
| `Double` | 부동소수점 수(floating-point number): 소수 부분을 표현할 수 있는 수 | 확대 배율 `1.5` |
| `String` | 문자열(string): 글자들의 모음 | 문서 이름 `"공부.pdf"` |
| `Bool` | 불리언(Boolean): 참 또는 거짓 | 미저장 변경이 있는지 나타내는 `true` 또는 `false` |

`Double`은 모든 소수를 정확하게 저장하는 타입은 아닙니다. 여기서는 `1.5`처럼 배율을 표현할 때 쓴다는 정도로 이해하면 됩니다. `true`는 참, `false`는 거짓이며 따옴표 없이 씁니다.

```swift
let page: Int = 3
let zoom: Double = 1.5
let title: String = "공부.pdf"
let hasChanges: Bool = false
print(page, zoom, title, hasChanges)
```

예상 결과는 `3 1.5 공부.pdf false`입니다. 첫 네 줄은 각각 이름, 타입, 값을 정합니다. `이름: 타입` 형태의 `:`는 이름에 어떤 종류의 값을 넣을지 표시합니다. 마지막 줄은 네 값을 쉼표로 나누어 `print`에 전달합니다. `print`는 기본적으로 값 사이에 공백을 넣습니다.

앞의 예제에서 타입을 쓰지 않아도 된 이유는 Swift가 `3`을 보고 `Int`라고 판단할 수 있기 때문입니다. 이를 타입 추론(type inference)이라고 합니다. 타입이 없어진 것이 아니라 작성할 때 생략할 수 있는 것입니다.

**작은 연습:** 쪽 번호 `3`과 따옴표로 감싼 `"3"`은 같은 타입일까요? **해설:** 아닙니다. 앞은 계산할 수 있는 정수, 뒤는 숫자 모양의 글입니다. `"3" + "1"`은 문자열을 이어 붙인 `"31"`이며, `3 + 1`은 정수 `4`입니다.

## 0.5 조건에 따라 행동을 고릅니다

조건문(conditional statement)은 조건이 참인지 거짓인지에 따라 실행할 코드를 고릅니다. Swift에서는 `if` 뒤에 조건을 적습니다. `<`는 “왼쪽이 오른쪽보다 작다”를 뜻합니다.

```swift
let pageCount = 5
var currentPage = 5
if currentPage < pageCount {
    currentPage = currentPage + 1
}
print(currentPage)
```

예상 결과는 `5`입니다. 첫째·둘째 줄에서 전체 쪽 수와 현재 쪽을 모두 `5`로 정합니다. 셋째 줄의 `5 < 5`는 거짓이므로 중괄호 `{ ... }` 안의 넷째 줄은 실행하지 않습니다. 마지막 줄은 그대로인 `5`를 표시합니다.

두 값이 같은지 비교할 때는 `==`를 씁니다. 예를 들어 `currentPage == pageCount`는 “현재 쪽이 마지막 쪽인가?”라는 질문이며, 결과는 `true` 또는 `false`입니다. `=`는 값을 넣고, `==`는 같은지 묻는다는 차이를 기억하세요.

**작은 연습:** 둘째 줄만 `var currentPage = 4`로 바꾸면 어떻게 될까요? **해설:** `4 < 5`가 참이므로 중괄호 안을 실행합니다. `4 + 1`을 대입해 최종 결과는 `5`입니다.

이 코드는 현재 쪽이 처음부터 올바른 번호라는 가정에서 동작하는 작은 모형입니다. `0`이나 음수 입력까지 처리하는 실제 검사는 [4장](04-ALGORITHMS-UNDO.md)에서 배웁니다.

## 0.6 여러 값을 배열에 모읍니다

배열(array)은 여러 값을 순서대로 담는 모음입니다. 각 값을 원소(element)라고 하며, 대괄호 `[...]`로 묶고 쉼표로 구분합니다. 배열에서 위치를 나타내는 번호는 인덱스(index)라고 합니다. Swift 배열의 첫 인덱스는 `0`입니다.

```swift
let selectedPages = [1, 3, 5]
print(selectedPages[0])
print(selectedPages[1])
print(selectedPages.count)
```

예상 결과는 순서대로 `1`, `3`, `3`입니다. 첫 줄은 선택한 쪽 번호 세 개를 배열로 만듭니다. 둘째 줄은 첫 번째 원소인 `1`, 셋째 줄은 두 번째 원소인 `3`을 표시합니다. 마지막 줄의 `.count`는 배열에 들어 있는 원소의 개수인 `3`을 읽습니다.

여기서 **쪽 번호와 배열 인덱스는 다릅니다.** `selectedPages[1]`은 “1쪽”이 아니라 “배열의 두 번째 칸에 담긴 값”입니다. 그 칸에 들어 있는 쪽 번호가 `3`입니다.

| 배열 인덱스 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| 저장한 쪽 번호 | 1 | 3 | 5 |

**작은 연습:** `selectedPages[2]`의 값은 무엇일까요? **해설:** 세 번째 칸의 값인 `5`입니다. 이 배열에는 인덱스 `3`이 없으므로 `selectedPages[3]`을 읽으면 실행이 중단됩니다. 원소가 세 개라고 마지막 인덱스가 `3`인 것은 아닙니다.

## 0.7 같은 작업은 반복문으로 처리합니다

반복문(loop)은 비슷한 일을 여러 번 실행합니다. 다음의 `for ... in ...`은 배열에서 값을 하나씩 꺼내 같은 동작을 합니다.

```swift
let selectedPages = [1, 3, 5]
for page in selectedPages {
    print(page)
}
print("완료")
```

예상 결과는 `1`, `3`, `5`, `완료`가 각각 한 줄씩 표시되는 것입니다. 첫 줄은 배열을 준비합니다. 둘째 줄은 원소를 순서대로 꺼내 그때마다 `page`라는 이름으로 사용합니다. 셋째 줄은 꺼낸 값을 표시합니다. 반복이 모두 끝나면 마지막 줄을 한 번 실행합니다.

`page`에는 첫 번째 반복에서 `1`, 다음 반복에서 `3`, 마지막 반복에서 `5`가 들어옵니다. 이 반복문은 배열 **인덱스가 아니라 원소의 값**을 꺼냅니다.

**작은 연습:** 배열을 `[2, 2]`로 바꾸면 `2`는 몇 번 표시될까요? **해설:** 두 번입니다. 배열은 같은 값을 여러 번 담을 수 있으며, 반복문은 두 원소를 각각 처리합니다. 이어서 `완료`가 한 번 표시됩니다.

## 0.8 동작에 이름을 붙이면 함수가 됩니다

앞에서 `print`를 호출했습니다. 이제 직접 함수를 만들어 봅니다. 함수는 입력(input)을 받아 작업하고, 결과를 반환(return)할 수 있습니다. 다음은 1부터 세는 쪽 번호를 0부터 세는 인덱스로 바꾸는 함수입니다.

```swift
func pageIndex(pageNumber: Int) -> Int {
    return pageNumber - 1
}
let index = pageIndex(pageNumber: 3)
print(index)
```

예상 결과는 `2`입니다. 한 줄씩 읽으면 다음과 같습니다.

1. `func`는 함수를 정의합니다. 이름은 `pageIndex`이고, `pageNumber: Int`는 정수 입력을 받을 자리입니다. `-> Int`는 반환할 결과도 정수라는 뜻입니다.
2. `return`은 입력에서 `1`을 뺀 값을 호출한 곳으로 돌려줍니다.
3. `}`는 함수 내부 코드의 끝입니다.
4. 함수를 실제로 호출하면서 입력 `3`을 전달합니다. 돌려받은 `2`를 `index`에 넣습니다.
5. `index`에 들어 있는 `2`를 표시합니다.

정의에서 입력을 받을 자리인 `pageNumber`를 매개변수(parameter), 호출할 때 전달하는 구체적인 값 `3`을 인자(argument)라고 합니다. 처음에는 “받을 자리”와 “실제로 넣는 값”으로 구별하면 됩니다.

**함수를 정의하는 것과 호출하는 것은 다릅니다.** 첫 세 줄은 동작에 이름을 붙여 두는 일입니다. 넷째 줄에서 호출해야 둘째 줄의 계산이 실행됩니다. 또한 `return`은 결과를 돌려주는 동작이고, `print`는 결과를 표시하는 동작이므로 서로 바꿔 쓸 수 없습니다.

**작은 연습:** 넷째 줄의 입력을 `pageNumber: 1`로 바꾸면 무엇이 표시될까요? **해설:** `1 - 1`인 `0`입니다. 이 함수도 입력 검사가 없는 모형이므로, 실제 앱에서 사용하려면 `1` 이상인지 등의 확인이 필요합니다.

## 0.9 주석과 기호를 읽는 요령

주석(comment)은 사람이 읽도록 코드에 남기는 설명입니다. Swift에서 `//` 뒤부터 줄 끝까지는 실행하지 않습니다. 들여쓰기(indentation)는 줄 앞에 공백을 넣어 코드의 묶음을 보기 쉽게 만드는 것입니다. 다음 예제에서 중괄호 안을 네 칸 들여쓰면 조건에 속하는 줄이 눈에 잘 들어옵니다.

```swift
var currentPage = 3 // 처음 보는 쪽입니다.
if currentPage == 3 {
    currentPage = 4
}
print(currentPage)
```

예상 결과는 `4`입니다. 첫 줄은 값을 정하고 주석을 남깁니다. 둘째 줄은 값이 `3`인지 확인합니다. 참이므로 셋째 줄에서 `4`를 대입합니다. 마지막 줄은 바뀐 값을 표시합니다. Swift에서는 이런 코드 묶음을 중괄호로 구분하므로 들여쓰기 자체가 조건의 범위를 결정하지는 않습니다.

아래 표는 **이 장에서 만난 쓰임**만 정리한 것입니다. 같은 기호가 다른 문맥에서 다른 역할을 할 수도 있으므로, 모든 뜻을 한 번에 외울 필요는 없습니다.

| 기호 | 이 장에서 읽는 방법 | 예 |
| --- | --- | --- |
| `()` | 함수에 전달할 입력을 둘러쌉니다. | `print(3)` |
| `{}` | 함께 실행할 코드의 묶음을 둘러쌉니다. | `if`의 내부, 함수의 내부 |
| `[]` | 배열을 만들거나 배열의 위치를 지정합니다. | `[1, 3, 5]`, `selectedPages[0]` |
| `.` | 값에 딸린 정보를 읽습니다. | `selectedPages.count` |
| `:` | 타입을 적거나 호출할 입력의 이름을 구분합니다. | `page: Int`, `pageNumber: 3` |
| `=` | 오른쪽 값을 왼쪽에 넣습니다. | `currentPage = 4` |
| `==` | 두 값이 같은지 비교합니다. | `currentPage == 3` |
| `->` | 함수가 반환하는 값의 타입 앞에 붙입니다. | `-> Int` |
| `""` | 문자열의 시작과 끝을 표시합니다. | `"공부.pdf"` |
| `//` | 뒤의 내용을 사람을 위한 주석으로 남깁니다. | `// 처음 보는 쪽입니다.` |

**작은 연습:** 첫 줄의 주석만 `// 여기는 메모입니다.`로 바꾸면 결과가 바뀔까요? **해설:** 아닙니다. 주석은 실행하지 않으므로 결과는 여전히 `4`입니다.

## 0.10 화면에서 바뀐 것과 파일에 저장된 것은 다릅니다

메모리(memory)는 실행 중인 프로그램이 값을 두고 사용하는 공간입니다. 파일(file)은 프로그램을 종료한 뒤에도 다시 읽을 수 있도록 저장 장치에 남긴 데이터입니다. 우리 앱에서 편집 중인 문서와 디스크(disk)에 저장한 PDF 파일은 구분해서 생각해야 합니다.

메모리를 **작업 중인 책상**, 저장 파일을 **보관해 둔 문서**에 비유해 보겠습니다. 책상 위에서 페이지 순서를 바꿨다고 보관한 문서까지 저절로 바뀌지는 않습니다. 앱은 저장 기능을 통해 편집 결과를 파일에 반영합니다. 화면의 쪽 번호를 바꾸는 것과 PDF 내용 자체를 편집하는 것 역시 서로 다른 동작입니다.

이 비유가 실제 저장 방식을 전부 설명하지는 않습니다. 자동 저장이나 임시 파일을 쓰는 앱도 있으며, 저장이 실패할 수도 있습니다. 여기서는 **값을 바꾸는 일과 그 값을 파일로 남기는 일을 별도로 확인한다**는 원칙만 기억하세요. 우리 앱이 기존 파일을 보호하면서 저장하는 순서는 [5장](05-SAVING-OCR.md)에서 배웁니다.

**생각해 보기:** `var currentPage = 3`을 `4`로 바꾸면 PDF 파일도 수정될까요? **해설:** 이 장의 예제에는 파일을 쓰는 동작이 없습니다. 숫자 값만 바뀝니다. 코드를 읽을 때는 “어떤 값이 바뀌는가?”와 “어디에 저장하는가?”를 따로 질문하세요.

## 0.11 터미널은 코드를 붙여 넣는 곳일까요?

터미널(terminal)은 글로 명령(command)을 입력해 컴퓨터에 작업을 요청하는 도구입니다. 명령은 “폴더 위치를 알려 줘”, “이 파일을 실행해 줘” 같은 요청입니다. Swift 코드와 터미널 명령은 다릅니다. `var currentPage = 3` 같은 Swift 코드를 터미널에 그대로 입력한다고 Swift 프로그램으로 실행되지는 않습니다.

터미널에는 **현재 폴더**(current directory)가 있습니다. 다음은 코드를 실행하는 실습이 아니라, 현재 폴더의 위치를 알아보는 터미널 명령입니다.

```sh
pwd
```

결과는 현재 폴더의 경로(path), 즉 위치를 나타내는 글입니다. 결과가 `/Users/이름/Documents`처럼 보일 수 있지만, 실제 내용은 사용하는 컴퓨터와 현재 위치에 따라 달라집니다. 이 명령 자체는 파일을 바꾸지 않습니다.

`cd`는 현재 폴더를 바꾸는 명령입니다. 예를 들어 현재 폴더 안에 `PDF 공부`라는 폴더가 **실제로 있을 때만** 다음 명령으로 그곳에 들어갈 수 있습니다.

```sh
cd "PDF 공부"
```

이것은 경로 문법을 설명하는 예이며, 먼저 해당 폴더를 만들라는 뜻은 아닙니다. 따옴표는 공백이 들어 있는 폴더 이름을 하나로 묶습니다. 위 명령이 성공하면 보통 별도의 결과 문구 없이 입력할 자리가 다시 나타납니다. 그때 `pwd`를 실행하면 이동한 위치를 확인할 수 있습니다. 폴더가 없으면 오류가 표시됩니다.

### 우리 프로젝트에서 실제로 실행해 보기

아래는 프로젝트를 홈 폴더의 `Projects/HwattakPDF`에 내려받았다고 가정한 예입니다. 첫 줄의 경로를 실제 프로젝트 위치에 맞게 바꾸세요. Swift 도구가 설치되어 있다면 첫 줄을 입력하고 Return 키를 누른 뒤, 폴더 이동이 성공했는지 확인하고 둘째 줄을 실행해 보세요.

```sh
cd "$HOME/Projects/HwattakPDF"
swift Examples/Learning/SwiftFirstSteps/main.swift
```

첫 줄은 프로젝트 폴더로 이동합니다. `$HOME`은 현재 사용자의 홈 폴더를 뜻합니다. 둘째 줄은 그 폴더 안에 있는 Swift 첫 실습 파일을 실행합니다. `swift`는 실행할 도구의 이름이고, 그 뒤는 실행할 소스 파일의 경로입니다. `cd`가 실패했다면 폴더 위치부터 확인한 뒤 다음 명령을 실행하세요.

결과에는 `전체: 5페이지`, `시작: 1페이지` 등이 표시됩니다. 전체 예상 결과와 숫자 하나를 바꾸는 방법은 [Swift 첫걸음 안내](../../Examples/Learning/SwiftFirstSteps/README.md)에 있습니다. 이 프로그램은 실제 앱과 PDF를 수정하지 않습니다.

Swift 실행 도구가 준비되기 전에는 이 장의 **예측 → 한 줄씩 읽기 → 해설 비교**만 해도 됩니다. “명령을 찾을 수 없다”는 오류는 도구 준비 문제이고, “파일을 찾을 수 없다”는 오류는 현재 폴더나 경로 문제일 수 있습니다. Rust 도구 준비와 명령 실행은 [7장](07-RUST.md)에서 따로 다룹니다.

## 0.12 다음 장으로 넘어갈 준비

아래 질문에 자기 말로 한 문장씩 답해 보세요. 막히면 괄호에 표시한 절만 다시 읽으면 됩니다.

- `currentPage = currentPage + 1`은 왜 가능한가요? 오른쪽을 먼저 계산한 값을 다시 넣기 때문입니다. (0.3)
- `=`와 `==`는 무엇이 다른가요? 하나는 대입하고, 다른 하나는 같은지 비교합니다. (0.5)
- 배열의 첫 값은 왜 `[1]`이 아닌 `[0]`으로 읽나요? Swift 배열의 인덱스가 `0`부터 시작하기 때문입니다. (0.6)
- 함수를 적어 두기만 해도 함수 내부가 실행되나요? 아닙니다. 호출할 때 실행됩니다. (0.8)
- 숫자를 바꾸면 파일도 저장되나요? 파일에 쓰는 별도의 동작이 없다면 저장되지 않습니다. (0.10)
