# OCR 사본 저장 실패 수정 — 2026-09-25

## 원인과 재현

OCR 내보내기는 저장할 폴더에 `.<전체 파일명>.<UUID>.ocr.tmp`를 먼저 만들고 결과를 선택한 파일로 이동했다. macOS 저장 창에서 선택한 파일 하나에만 쓰기 권한이 생기는 경우, 옆의 임시 파일은 허용되지 않아 `CGDataConsumer` 생성 단계에서 실패했다. 기존 일반 PDF 저장기의 파일 단위 권한 대응 경로를 OCR 내보내기에서는 사용하지 않았다.

제보 화면의 파일명을 사용한 합성 문서로 별도 샌드박스 정책을 적용했다. 선택한 파일 경로에만 쓰기를 허용하고 같은 폴더의 다른 경로는 금지했을 때, 기존 임시 파일 생성은 실패하고 선택한 파일 직접 쓰기는 성공했다. 이 파일명 자체는 길이 제한 안에 있었다. 추가로, 다른 유효한 긴 파일명에는 UUID를 붙인 임시 파일명이 제한을 넘어 실패하는 문제도 확인했다.

## 변경

- OCR 페이지는 사용자만 접근 가능한 앱 임시 폴더에 완성하고 검증한다.
- 검증된 PDF를 공통 `AtomicPDFWriter`로 저장한다. 폴더 쓰기가 허용되면 임시 파일 교체를 사용하고, 선택한 파일에만 쓰기 권한이 있으면 검증 후 해당 파일에 쓰는 기존 경로를 사용한다.
- 공통 저장기의 임시 파일명은 원본 이름을 덧붙이지 않고 짧은 UUID 기반 이름을 사용한다.
- 원본과 같은 경로·심볼릭 링크·하드 링크 차단과, 결과 생성 중 다른 프로그램이 바꾼 저장 대상 보호를 유지한다.
- 시스템이 반환한 권한·디스크·입출력 오류 이유를 보존한다. OCR 화면에는 저장 실패 이유와 인식 결과를 다시 저장할 수 있다는 안내를 표시한다.

## 검증

- 새 저장 회귀 검사 7개 통과: 한글 조합·분해형 긴 이름, 기존 파일 교체, 파일 하나만 쓰기 가능한 조건, 저장 도중 대상 생성·교체, 디스크 부족 오류 보존, 재인식 없는 재저장.
- 페이지 처리·OCR 적용·외부 변경 충돌·번역 검사 60개 통과.
- PDF 보안 검사 19개 통과. 이번 수정 관련 합계 86개이며 전체 테스트 묶음을 실행했다는 의미는 아니다.
- 10개 번역과 프로젝트 정적 검사 통과. 테스트 묶음 목록은 전체 72개 클래스와 일치한다.
- 실제 변경된 `SearchablePDFExporter`, `AtomicPDFWriter`, `SecurityScopedAccess` 소스를 합성 문서 실행기에 연결해 macOS 샌드박스 안에서 실행했다. 존재하지 않던 선택 파일만 생성할 수 있고 임시 형제 파일은 생성할 수 없는 조건에서 새 PDF 생성, 페이지 수, OCR 텍스트를 확인했다. 같은 실행기에서 기존 방식의 임시 파일 생성 실패도 확인했다. 사용자 PDF는 재현에 사용하지 않았다.

개발 검사에서 일반 쓰기 가능한 폴더만 확인하여 배포 앱의 파일 단위 권한 조건을 놓쳤던 검증 공백을 보완한다. 재현 실행기·정책은 로컬 `work/tmp/ocr-save-diagnosis`에 보관한다.
