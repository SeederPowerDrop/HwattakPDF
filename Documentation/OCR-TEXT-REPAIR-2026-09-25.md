# 기존 OCR 오류로 한글 검색이 누락되는 문제 — 2026-09-25

## 원인

보고된 PDF의 51쪽은 이미지에 ‘췌장’이 보이지만 기존 검색용 텍스트에는 ‘훼장’, ‘춰|장’으로 들어 있었다. 해당 페이지의 기존 추출 텍스트 383자에서 ‘췌장’은 0회였다. 검색기의 한글 조합 정규화 문제는 아니었다.

기존 OCR 기본 설정은 공백을 제외한 텍스트가 24자 이상이면 인식을 건너뛰었다. 따라서 이미 텍스트가 있는 스캔의 잘못된 인식 결과를 고치지 못했다. 검색 화면의 ‘텍스트 없는 8페이지’ 안내는 이 페이지의 인식 오류를 설명하지 못했다.

## 변경

- OCR 기본값을 기존 텍스트가 있는 페이지도 다시 인식하도록 변경했다. 사용자가 건너뛰기를 켜면 기존 인식 오류도 유지될 수 있음을 알린다.
- 새 인식 결과가 있는 기존 텍스트 페이지는 선택한 해상도의 페이지 이미지와 새 검색용 텍스트로 구성한다. PDF를 직접 다시 그리면서 잘못된 옛 텍스트까지 중복 복사하던 문제를 막는다.
- 기존 텍스트가 없는 스캔은 원본 페이지 그리기를 유지한다. 건너뛴 페이지 또는 새 인식 결과가 전혀 없는 페이지의 기존 텍스트도 보존한다.
- 새 PDF 저장은 문서 사본을 바탕으로 백그라운드에서 처리하고 저장 중 상태를 표시한다. 현재 문서에 적용한 뒤에는 입력되어 있던 검색어로 다시 검색한다.
- 검색 결과가 없을 때 텍스트가 있는 PDF에도 재인식 안내와 OCR 버튼을 표시한다. 완료 후 현재 PDF에 적용하거나 새로 저장한 PDF를 열도록 안내한다.
- 해상도에 따른 변환을 OCR 안내와 적용 확인에 명시하고 10개 언어에 반영했다. 좁은 검색 패널에서 안내가 길어지면 스크롤할 수 있다.

## 실문서 검증

원본은 읽기만 했고, 검증은 별도의 한 페이지 사본으로 수행했다. Apple Vision의 정확 인식·220 DPI·언어 교정 사용 조건에서 한국어/영어, 기본 한국어/영어/일본어 모두 제목 ‘췌장액의 비밀’과 ‘췌장’ 10회를 인식했다.

실제 제품의 SearchablePDFExporter로 이 인식 결과를 저장한 뒤 PDF를 다시 열었다. 제품 검색기 PDFSearchEngine에서 ‘췌장’ 10개 결과와 각 결과의 PDFSelection 문자열·범위를 확인했다. 기존 ‘훼장’ 텍스트는 결과에 남지 않았고 검증 입력 파일은 바이트 단위로 그대로였다. 출력 페이지 이미지를 확인해 방향과 배치도 검토했다.

OCR 재인식·저장·적용·페이지 처리 회귀 검사 57개(재인식 5, 저장 7, 적용 9, 페이지 처리 36), 검색·검색 화면·번역 검사 29개, 보안 검사 19개, 별도의 실문서 검증 1개가 통과했다. 관련 자동 검사 총 105개와 실문서 검증 1개이며, 비동기 저장 중 UI 응답·저장 대상 외부 변경 보존·적용 뒤 기존 검색어 재검색도 포함한다. 재인식 검사에는 네 방향 회전과 0이 아닌 CropBox 원점, 기존 텍스트 보존 조건, 검색 결과 선택을 포함했다. 이 수치는 전체 테스트 묶음 실행을 뜻하지 않는다.

검증 자료와 화면 이미지는 로컬 `work/ocr-text-repair`에만 보관하며 배포 앱이나 테스트 자료에 사용자 문서 내용을 포함하지 않는다. 현재 실행 중인 앱과 원본 PDF는 변경하지 않았다.
