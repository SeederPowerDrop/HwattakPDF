## 1. 제품 한 문장

HwattakPDF는 여러 PDF를 탭에서 함께 관리하고 비교하면서 빠르게 읽고 공부하며, 페이지 조립·주석·서명·OCR까지 로컬에서 처리하는 macOS용 PDF 작업 공간이다.

핵심은 기능 개수만 늘리는 것이 아니다. 사용자가 자신의 파일과 작업 결과를 계속 소유하고, 어떤 기능이 실제 PDF 본문을 바꾸는지 또는 주석을 덧붙이는지 알 수 있으며, 큰 문서에서도 중간 결과를 잃지 않는 것이 우선이다.

## 2. 제품 원칙

1. **로컬 우선**: 보기, 페이지 조작, 주석, 서명, 기본 OCR은 계정이나 외부 서버 없이 동작한다.
2. **파일 소유권**: 결과물은 특정 앱에 갇힌 프로젝트 포맷이 아니라 다른 표준 PDF 뷰어에서도 열리는 PDF여야 한다.
3. **기능을 과장하지 않기**: 자유 텍스트 주석을 “기존 본문 편집”이라고 부르지 않고, 손글씨 서명을 “인증서 기반 디지털 서명”이라고 부르지 않는다.
4. **데이터 손실 방지**: 저장은 검증된 임시 파일의 원자 교체를 우선하고, 파일 단위 권한 때문에 불가능하면 완전한 PDF를 먼저 직렬화·검증한 뒤 직접 쓰고 다시 검증한다. 오래 걸리는 작업은 페이지 단위 체크포인트와 재개 기능을 갖춘다.
5. **Mac다운 사용성**: 키보드 단축키, 가벼운 트랙패드 터치, Finder 및 파일 제공자, 다중 선택과 드래그 앤 드롭을 자연스럽게 지원한다.
6. **공부에 좋은 읽기 경험**: 한 페이지 확대뿐 아니라 2페이지 대조, 최대 12페이지 개요, 검색, 하이라이트, 메모와 펜을 일관된 흐름으로 제공한다.
7. **업데이트 약속을 명시적으로 관리**: 공식 기본 앱은 구독과 광고 없이 무료로 제공한다. 향후 배포 정책이 바뀌더라도 “평생” 같은 모호한 표현 대신 지원 기간, 무상 업데이트 범위와 유료 메이저 업그레이드 여부를 버전별로 먼저 공개한다.
8. **iPad를 막지 않는 설계**: 지금은 Mac에 집중하되 문서 연산, OCR 작업 모델과 주석 데이터는 향후 iPad UI에서도 재사용할 수 있게 분리한다.
9. **외부 AI는 명시적 선택**: 기본 PDF 기능은 AI 없이 동작하고, 전송할 공급자·문서 범위·대화·도구를 요청마다 보여 준 뒤 동의받는다.

## 3. 해결할 사용자 문제

### 3.1 주요 사용자

- 수백~수천 페이지 전공 교재와 논문을 읽고 표시하는 학생·연구자
- 계약서, 신청서, 견적서를 조립하고 서명하는 개인 및 소규모 팀
- 스캔 자료를 검색 가능한 PDF로 장기간 보관하려는 사용자
- 구독이나 서버 업로드 없이 민감한 PDF를 처리하려는 Mac 사용자
- 여러 클라우드 위치의 PDF를 Finder처럼 열고 다시 저장하려는 사용자

### 3.2 핵심 작업

- 큰 PDF를 빠르게 열고 1·2·3·4페이지 단위로 훑는다.
- 여러 PDF를 독립된 탭으로 열고 전환·정렬·닫으며, 같은 파일을 실수로 중복해서 열지 않는다.
- 열린 PDF 중 2~4개를 좌우 또는 위아래로 함께 보고, 필요에 따라 스크롤을 동기화하거나 특정 문서를 잠근다.
- 썸네일을 보며 페이지를 재정렬·회전·삭제하고, 선택 페이지만 추출하거나 다른 PDF를 삽입한다.
- 새 텍스트·이미지·주석을 정확한 위치에 추가하고, 원문을 직접 고치지 않는 시각적 텍스트 교체가 필요하면 그 한계를 확인한 뒤 오버레이로 처리한다.
- 텍스트를 검색·선택·하이라이트하고 메모와 펜 필기를 남긴다.
- 버튼으로 트랙패드 입력을 활성화한 뒤 한 손가락 움직임으로 서명하거나, 나중에는 iPhone/iPad에서 받아온 서명을 넣는다.
- 이미지형 PDF에 무료 로컬 OCR을 실행하고, 중단되어도 완료 페이지부터 재개한 뒤 검색 가능한 PDF를 만든다.
- 여러 이미지·로컬 HTML·기존 PDF의 선택 페이지와 공백 페이지를 원하는 순서로 묶고, 필요하면 OCR 텍스트도 함께 얻는다.
- PDF의 페이지별 보이는 모양을 Word 또는 PowerPoint에서 열 수 있는 파생 문서로 내보낸다.
- iCloud Drive 또는 Finder 파일 제공자를 통해 파일을 열고 충돌 없이 저장한다.

### 4.3 이용자가 원하는 것으로 추론되는 공통 기능

주요 제품에서 반복되는 기능과 최초 요구를 함께 보면 다음 우선순위가 드러난다.

1. **빠르고 정확한 렌더링**: 큰 교재에서도 스크롤과 확대가 끊기지 않고 글자·이미지가 정확해야 한다.
2. **문맥에 맞는 보기 방식**: 단일 페이지, 책처럼 마주 보는 2페이지, 여러 페이지를 훑는 개요가 필요하다. HwattakPDF의 3·4열은 기존 2페이지 중심 제품과 구별되는 핵심이다.
3. **안전한 페이지 조립**: 재정렬, 회전, 삭제, 추출, 삽입·병합이 눈에 보이고 되돌릴 수 있어야 한다.
4. **진짜 내용 편집**: 새 텍스트 상자를 올리는 것뿐 아니라 기존 텍스트의 오탈자와 이미지 객체를 직접 수정하려는 수요가 크다.
5. **공부와 검토 도구**: 검색, 하이라이트, 밑줄, 메모, 자유 필기, 책갈피 및 주석 목록이 필요하다.
6. **신뢰할 수 있는 서명**: 손으로 그린 서명과 법적·기술적 무결성을 증명하는 인증서 서명을 구분해서 제공해야 한다.
7. **검색 가능한 OCR 결과**: 앱 안에서만 보이는 인식 결과가 아니라 다른 뷰어에서도 검색·복사되는 PDF가 필요하며, 결과 검수와 재처리도 중요하다.
8. **대용량 안정성**: 페이지별 진행 상황, 취소, 재개, 오류 페이지 재시도, 충분한 저장 공간 확인이 필요하다.
9. **클라우드가 선택 사항인 흐름**: 로컬 파일과 iCloud·Drive·Dropbox 등을 같은 열기/저장 UI에서 다루되, OCR을 위해 문서를 임의 업로드하지 않아야 한다.
10. **예측 가능한 비용과 유지보수**: 핵심 기능을 나중에 조용히 잠그지 않고, 지원 정책과 유료 범위를 사전에 설명해야 한다.

2026년 한 커뮤니티 토론에서도 인쇄의 기본 동작, 외부 앱에서도 검색되는 OCR PDF, OCR 결과 검수, 예측 가능한 파일명과 배치 작업 이력 같은 “평범하지만 실패하면 치명적인” 요구가 반복됐다. 이는 대표성 있는 설문이 아니라 우선순위를 보정하는 참고 자료다. ## 5. 0.9.0 배포 패키지의 구현 범위

0.9.0 (build 19) Developer Preview는 2026-09-22에 준비한 로컬 배포 패키지다. 아래 이미지·HTML·Office 변환 기능도 포함하며, 마지막 GitHub 공개 배포본인 0.8.0 (build 18)과 구분한다. 패키지 포함 여부와 실제 Office·기기별 수동 호환성 검증 완료는 별개다. 이번 검증 범위는 [0.9.0 배포 검증 기록](RELEASE-VALIDATION-0.9.0.md)을 따른다.

상태 표기:

- **구현**: 현재 소스에 동작 경로가 있다.
- **부분 구현**: 제한된 형태로 동작하지만 완성 기능으로 표현하면 안 된다.
- **다음 단계**: 설계 방향만 있고 현재 동작하지 않는다.

### 5.1 중요한 표현상의 한계

- 현재의 에디팅 인라인 텍스트와 “시각적 텍스트 교체”는 PDF 표준 FreeText **주석 오버레이**를 다룬다. 원래 콘텐츠 스트림의 본문을 직접 수정하거나 삭제하지 않으므로 가린 원문이 검색·복사·접근성 추출에 남을 수 있고, 보안 삭제나 secure redaction으로 사용할 수 없다.
- 현재의 이미지 편집은 페이지 위에 추가한 **스탬프 주석**을 다루며, 원래 콘텐츠 스트림의 이미지 객체를 편집하지 않는다. 자르기는 삽입 세션이 보유한 원본 이미지에 적용되므로 저장 후 다시 연 스탬프는 에디팅 모드에서 이동·크기·레이어 편집은 가능하지만 재자르기는 제공하지 않는다. 공개 marker 문자열은 권한 증명이 아니므로 뷰어·학습 모드는 현재 실행에서 생성·명시 편집한 주석만 파괴적으로 조작한다.
- 학습 모드의 색상·두께·진하기 조절형 하이라이트/밑줄은 PDFKit의 투명도 저장 한계를 피하려고 appearance를 가진 표준 **Stamp**로 저장한다. 외부 뷰어에서 보이는 모양을 유지하기 위한 출력이며, 의미론적 Highlight/Underline subtype이나 재개방 후 앱 전용 조절형 표식 편집 모델은 아니다.
- 현재 Mac 펜 입력은 마우스·트랙패드와 Sidecar가 전달한 Apple Pencil 포인터 이벤트를 받는다. Apple Pencil을 Mac에 직접 연결하거나 PencilKit의 압력·기울기 데이터를 네이티브로 받는 구현은 아니다.
- 현재의 트랙패드 서명은 눈에 보이는 **그래픽 서명**이다. 서명 후 변조 여부를 암호학적으로 증명하는 인증서 서명이 아니다.
- 개발용 ad-hoc 배포본의 기본 서명은 현재 로그인 사용자의 비동기화 login Keychain 호환 경로를 쓴다. `WhenUnlockedThisDeviceOnly`와 업데이트 간 안정적인 앱 전용 접근은 정식 Developer ID/App Store 프로비저닝 및 Keychain access group을 구성한 배포본에서 보장해야 한다.
- 현재 OCR은 보이는 페이지와 주석 외관을 새 PDF에 평면화하고 인식한 글자를 보이지 않는 텍스트 레이어로 내보낸다. 링크·폼의 상호작용이나 기존 전자서명을 보존하지 않으며, 원래 레이아웃의 편집 가능한 본문 객체로 복원하는 기능도 아니다.
- PDF 만들기의 HTML은 일반 웹 탐색 기능이 아니다. 현재 UI는 비영구 WebKit 세션에서 원본 HTML과 같은 폴더 아래의 로컬 자원만 읽고 HTTP·HTTPS 자원을 차단하도록 구성했지만 완전한 네트워크 방화벽을 보증하지 않는다. 문서 안의 JavaScript도 실행하므로 신뢰할 수 없는 HTML을 안전하게 정화하는 기능으로 소개하지 않는다.
- 안정성·속도 예상치는 입력 metadata 기반 휴리스틱 범위다. 두 방식 모두 PDFKit 조립은 순차 처리하며, 속도 우선 HTML도 안정성 우선과 같은 벡터 출력 경로를 사용한다. DOCX/PPTX 역시 보이는 페이지 이미지를 담는 파생 문서이지 편집 가능한 본문 변환이 아니다.
- 현재 문서 검색은 PDF의 기존 텍스트 층을 대상으로 하는 Unicode 부분 문자열 검색이다. 대소문자·발음 구별 부호·전각/반각·연속 공백·줄바꿈 하이픈은 정규화하지만 간체↔번체, 히라가나↔가타카나, 형태소·동의어·번역 의미를 자동 동치로 취급하지 않는다. 결과가 20,000개를 넘으면 일부만 표시하며, 내장 로컬 OCR 언어 선택은 현재 한국어·영어·일본어다.
- 파일 패널에서 클라우드 제공자 위치를 여는 것과 해당 서비스 API를 앱에 직접 통합하는 것은 다르다.
- 재실행 세션은 PDF 자체나 미저장 주석 바이트를 복제하지 않고 security-scoped bookmark와 보기 상태만 저장한다. 종료 확인에서 저장/버리기를 결정한 원본을 다시 열며, 분리 창의 개수와 workspace 소속은 복원하지만 정확한 화면 위치·크기는 기본 창 배치로 다시 생성된다.
- 현재 PDF 비교는 기존 탭의 보기 상태를 한 화면에 배치하고 정규화된 스크롤 진행률을 공유하는 기능이다. 파일 내용을 분석해 차이를 판정하거나 검토 결과를 생성하지 않는다.
- PDF AI와 학습 모드 AI 빠른 작업은 사용자가 공급자와 개발자 API 키를 설정해야 한다. 선택한 텍스트 문맥·대화·endpoint를 미리 보여 주고 요청별 명시 동의를 받은 뒤에만 외부 공급자 API에 보낸다. 공급자 정책과 모델 답변은 앱이 통제하거나 정확성을 보증하지 않으며, AI 초안은 사용자가 검토해 추가하는 자유 텍스트 주석이지 기존 본문·AcroForm 자동 편집이 아니다.
- 플러그인 schema 1(v1)은 실행 코드가 아니라 host-rendered 텍스트 템플릿이다. v1 `openURL`은 앱이 직접 요청하지 않고 공개 HTTPS host와 포함 데이터 종류를 매번 확인한 뒤 기본 브라우저로 연다. 설치 기록의 SHA-256은 `manifest.json` 변경 감지용이지 게시자 인증·코드 서명·notarization이 아니다.
- Schema 2도 package 코드를 실행하지 않고 앱 소유 패널만 선택한다. 패널 package와 `dev.hwattakpdf.` 식별자를 주장하는 모든 package는 검토 UI 전부터 앱 번들 검토본과 identifier+manifest SHA-256 digest가 정확히 같아야 설치·로드된다. 번역·YouTube·일반 브라우저는 별도 권한이며 browser/YouTube에는 PDF text bridge가 없다. WebKit은 공개 HTTPS top-level/response를 검사하고 script popup·download·upload·카메라/마이크 capture·file drag·deprecated TLS를 차단한다. 사용자 클릭인 표준 YouTube 링크만 exact host 확인 뒤 패널 또는 기본 브라우저로 보낸다. `.nonPersistent()`는 영구 profile을 피할 뿐 열린 세션의 원격 JavaScript·메모리 내 쿠키·tracking·subresource를 막는 network firewall이 아니다.

## 6. MVP 사용 흐름

모드 전환은 PDF를 복제하거나 저장 변경을 만들지 않는다. 읽기에 집중할 때 `⌃1` 뷰어, 콘텐츠를 덧붙이고 페이지를 조립할 때 `⌃2` 에디팅, 공부 도구를 모아 쓸 때 `⌃3` 학습으로 전환한다. 각 모드는 허용된 도구만 노출하며 현재 탭의 세션 상태로 복원된다.

### 6.1 교재 공부

1. Finder 또는 iCloud Drive에서 교재 PDF를 연다.
2. `⌃3`으로 학습 모드를 열고 1~12페이지 개요와 원하는 위치의 페이지 패널로 장과 페이지 구조를 훑는다.
3. 한 페이지 또는 2페이지 보기에서 검색하고 타이핑 메모나 마우스·트랙패드·Sidecar 포인터 필기를 남긴다.
4. 텍스트를 선택하고 하이라이트/밑줄의 색상·두께·진하기를 정해 적용한다.
5. 번역·용어 설명·요약·풀이 과정·학습 포인트·퀴즈를 고른 뒤 공급자·API 키·전송 범위를 확인하고 명시적으로 동의한다.
6. 필요한 선택문에는 bounded 메모를 덧붙여 일반 텍스트로 공유하고, PDF 변경은 저장 또는 별도 저장한다.

### 6.2 문서 조립

1. 기준 PDF를 연다.
2. `⌃2`로 에디팅 모드로 전환하고 여러 PDF를 병합한다.
3. 페이지 위에서 인라인 FreeText·이미지·서명 이미지를 추가하거나 펜으로 쓰고, 필요하면 원문 비삭제 경고를 확인한 뒤 시각적 텍스트 교체 오버레이를 사용한다.
4. 왼쪽 썸네일에서 페이지를 드래그해 순서를 바꾸고 불필요한 페이지를 삭제·회전한다.
5. 일부 페이지만 새 PDF로 추출한다.
6. 원본을 지키려면 별도 저장한다.

### 6.3 이미지·HTML·PDF 페이지에서 새 PDF 만들기

1. 파일 메뉴나 시작 화면에서 전용 `PDF 만들기` 창을 연다.
2. 여러 이미지와 로컬 HTML을 추가하고, 필요하면 다른 PDF에서 사용할 페이지만 고르거나 A4 공백 페이지를 넣는다.
3. 목록을 원하는 순서로 바꾸고 안정성 우선·속도 우선의 예상 시간과 용량 범위를 비교한다.
4. OCR이 필요하면 한·영·일 언어를 고른다. 선택한 처리 방식이 OCR DPI와 인식 품질도 함께 정한다.
5. 새 목적지에 저장하고 실제 시간·용량을 확인한다. OCR을 사용했다면 인식문을 복사하거나 UTF-8 텍스트로 따로 저장할 수 있다.

### 6.4 스캔 교재 OCR

1. OCR 시 한국어·영어·일본어와 DPI를 선택한다.
2. 기존 텍스트가 충분한 페이지는 건너뛴다.
3. 페이지별 진행률을 확인하고 필요하면 중단한다.
4. 같은 입력 데이터로 다시 시작해 완료된 페이지부터 재개한다.
5. 검색 가능한 사본을 새 PDF로 내보낸다.

### 6.5 여러 PDF 관리와 비교

1. 열기 패널을 사용하거나 PDF 본문·사이드바를 포함한 작업공간 어디에나 Finder의 여러 PDF를 드롭해 각각의 탭에 연다.
2. 탭을 전환하거나 드래그해 작업 순서를 정리한다.
3. 비교할 열린 PDF 2~4개와 패널 순서를 고른다.
4. 좌우 또는 위아래 배치를 선택하고 비율 기반 스크롤 동기화를 켠다.
5. 독립적으로 확인할 문서는 잠가 동기화의 송신과 수신에서 모두 제외한다.
6. 비교를 끝낸 뒤 각 탭으로 돌아가 필요한 문서를 개별 저장하거나 닫는다.

### 6.6 PDF AI로 읽고 초안 만들기

1. 설정에서 공급자·모델을 고르고 개발자 API 키를 Keychain에 저장한다.
2. PDF AI 패널을 열어 선택 텍스트, 현재 페이지, 선택 페이지 또는 문서 전체 대표 범위를 고른다.
3. 요약·분석·문제 풀이·채우기 초안 중 하나를 고르거나 질문을 입력한다.
4. 공급자, endpoint, 대화와 PDF 문맥의 전송량·미리보기를 확인하고 동의한다.
5. 웹/MCP를 쓴다면 외부 검색 전달을 확인하고 각 MCP 도구 이름·인자·서버 URL을 별도 승인한다.
6. 출처와 PDF 페이지 근거로 결과를 검토한다. 채우기 결과는 편집 시트에서 다시 확인한 뒤 주석으로 추가한다.

### 6.7 기본 웹 패널 플러그인 사용

1. `플러그인 > 플러그인 관리…`를 열고 `HwattakPDF 기본 플러그인`의 `번역 도우미`,
   `웹 브라우저` 가운데 필요한 항목을 찾는다.
2. `검토 및 설치`에서 각기 다른 권한과 identifier·version·SHA-256을 확인해 설치한다.
   앱 번들 검토본과 identifier+manifest digest가 정확히 일치하지 않는 웹 패널 package는
   설치할 수 없다.
3. 설치 목록의 검색으로 플러그인을 찾고 톱니바퀴 설정에서 활성 상태·권한·제공 action과
   설치 정보를 확인한다. 기본 플러그인은 번역 서비스·대상 언어, 브라우저 시작 페이지와
   검색 엔진 같은 전용 기본값도 정할 수 있지만 웹 보안 정책은 끌 수 없다.
4. 열린 PDF에서 상단 `플러그인` 버튼을 누르고 기본 플러그인 이름을 선택한다. 단일
   action인 웹 브라우저는 별도 하위 메뉴 없이 오른쪽 패널로 열리며, 집중 보기
   중 macOS 메뉴에서 실행해도 집중 보기를 끝내고 요청한 패널을 표시한다. 번역 도우미는 선택문 또는 현재
   페이지의 제한된 text snapshot을 보여 주며, 사용자가 편집·공급자·대상 언어·byte 수와
   대상 host를 확인하고 승인하기 전에는 외부 전송을 시작하지 않는다.
5. Google 번역은 승인한 짧은 text를 HTTPS query로 전송한다. ChatGPT·Claude는 승인한
   text를 번역 prompt로 일반 클립보드에 복사하고 사이트를 열므로, 사용자가 직접
   붙여넣고 보내야 실제 서비스 전송이 일어난다.
6. 일반 웹 브라우저는 공개 HTTPS 검색/주소만 열며 PDF text·파일 bridge가 없다.
7. 패널 사용을 마치면 닫는다. 문서 revision/identity 변경, 탭·scene 비활성화, 집중 보기,
   plugin disable/update/uninstall에도 패널과 비영구 WebView session은 폐기된다.

YouTube 학습 manifest와 호스트 지원 코드는 정책·동의 UI를 완성하기 위한 실험 경계다.
0.9.0 번들에도 검토본이 없으므로 위 사용자 흐름에서 설치하거나 실행할 수 없다.

## 7. 다음 단계 로드맵

### 단계 A — MVP 안정화

- 실행 취소/다시 실행, 자동 저장 또는 복구 저널
- 인쇄 및 표준 macOS 단축키 완성
- 복구 저널, 탭 고정, 분리 창 위치·크기 geometry를 포함한 범용 다중 창 문서 관리 검토
- 암호화·손상·혼합 페이지 크기·회전·양식·주석이 있는 PDF 회귀 테스트
- 100, 1,000, 수천 페이지 문서의 메모리·스크롤·OCR 스트레스 테스트
- 저장 전 여유 공간 확인, 실패 페이지 리포트, 접근성 및 VoiceOver
- 검색 가능한 OCR 사본에서 주석·링크·양식·북마크·메타데이터 보존 여부 검증 및 보강
- 지원 이미지 형식별 조립 fixture, 복잡한 로컬 CSS·글꼴·스크립트 HTML과 원격 자원 차단 검증
- Preview·Word·PowerPoint에서 PDF·DOCX·PPTX 파생 결과를 열어 페이지 크기·방향·시각 배치 수동 확인

### 단계 B — 실제 본문과 이미지 객체 편집

- 텍스트 콘텐츠 스트림, 폰트, 인코딩/CMap, 글자 위치를 분석하는 편집 모델
- 기존 텍스트 블록 선택, 수정, 재흐름, 폰트 대체 정책
- 페이지 리소스의 이미지 XObject와 인라인 이미지 탐색
- 원본 이미지 추출, 교체, 이동, 크기 조절, 자르기, 압축 품질 선택
- 링크, 영구 삭제(redaction), 머리말·꼬리말·페이지 번호

이 단계는 주석 기능의 단순 확장이 아니다. 다양한 PDF 생성기의 콘텐츠 스트림과 폰트 서브셋을 다뤄야 하므로 별도 편집 엔진과 대규모 호환성 픽스처가 필요하다.

### 단계 C — 선택 가능한 로컬 OCR 엔진

- 기본값은 별도 설치가 필요 없는 Apple Vision으로 유지한다.
- 엔진 프로토콜과 모델 관리자를 추가해 로컬 엔진을 선택할 수 있게 한다.
- 후보는 [OCRmyPDF](https://github.com/ocrmypdf/ocrmypdf), [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR), 필요 시 [Hugging Face의 TrOCR](https://huggingface.co/microsoft/trocr-base-handwritten) 계열이다.
- 모델별 언어, 다운로드 크기, 메모리 예상치, 라이선스, 체크섬, 출처, 정확도 프로필을 다운로드 전에 보여 준다.
- 임의 모델 코드를 실행하지 않고 검증된 런타임·형식만 허용한다.
- OCR 결과 박스와 읽기 순서를 검수·수정하고, 선택 페이지만 재인식할 수 있게 한다.

TrOCR 예시 모델은 한 줄 손글씨 인식용이므로 전체 PDF OCR의 즉시 대체재로 취급하지 않는다. OCRmyPDF는 대형 PDF 처리 경험이 많지만 Tesseract와 Ghostscript 같은 외부 의존성이 있어 설치·배포·라이선스 검토가 필요하다. PaddleOCR는 한국어를 포함한 다국어 모델 후보지만 macOS 배포 크기와 런타임 안정성을 실제 기기에서 검증해야 한다.

### 단계 D — 서명과 클라우드

- 여러 서명 보관함, 선택적 Touch ID 재인증과 Keychain migration 정책
- 서명 배치 후 이동·크기·색·평탄화 제어
- iPhone/iPad companion 또는 공개된 Apple 연속성 API 범위 내의 원격 서명 입력
- 인증서 기반 PDF 디지털 서명, 타임스탬프 및 유효성 검증
- NSDocument/NSFilePresenter 기반 지속적 외부 변경 알림과 두 버전 비교·병합
- 필요성이 확인된 서비스부터 OAuth 기반 Drive/Dropbox/OneDrive 브라우저 추가

### 단계 E — iPad

- SwiftUI 공통 화면과 플랫폼 독립 문서 연산 재사용
- UIKit PDFKit 및 PencilKit 기반 Apple Pencil 입력
- Files 문서 브라우저, iCloud 동기화, 백그라운드 작업 복구
- Mac과 같은 PDF 출력 호환성 테스트 세트 공유

## 8. 품질 기준

아래는 현재 달성 주장이라기보다 출시 판단에 사용할 목표다.

- 저장 중 종료되어도 기존 목적지 파일이 손상되지 않는다.
- 페이지 추출·병합·재정렬 후 페이지 수, 순서, 회전과 주요 주석이 유지된다.
- OCR 취소 후 같은 문서와 같은 설정으로 재개하면 완료 페이지를 다시 처리하지 않는다.
- OCR 출력은 미리보기, Acrobat 등 외부 뷰어에서 검색·선택할 수 있다.
- 3·4열 개요는 화면 밖 페이지 이미지를 모두 한꺼번에 메모리에 유지하지 않는다.
- 각 탭의 선택·페이지·편집·OCR 상태는 다른 탭과 섞이지 않고, 같은 파일을 다시 열면 기존 탭을 선택한다.
- 비교 화면은 2~4개 문서의 선택 순서와 잠금 설정을 지키며, 크기가 다른 문서 사이에서도 유한한 0~1 스크롤 진행률만 전달한다.
- 화면에 표시한 “완료”는 출력 파일을 다시 열어 최소 무결성 검증을 통과한 뒤에만 나타난다.
- PDF 만들기는 입력 순서와 확장된 HTML 페이지 수를 보존하고, 예상치를 보장값으로 표현하지 않으며, 처리 중 목록 변이를 허용하지 않는다.
- DOCX/PPTX는 페이지 이미지 기반임을 UI·README·릴리스 기록에서 동일하게 설명하고 실제 Office 앱 호환성 확인 전에는 편집 가능한 변환으로 표현하지 않는다.
- 실제 본문 편집, 이미지 객체 편집, 인증서 서명은 호환성 테스트를 통과하기 전까지 UI에서 구현된 것처럼 표시하지 않는다.
- PDF AI는 원본 파일이나 로컬 경로를 자동 전송하지 않고, 요청별 공급자·범위·총 사용자 콘텐츠와 도구를 확인한 뒤에만 네트워크를 사용한다.
- MCP는 모든 호출을 서버 URL·도구 이름·인자와 함께 보여 주고 승인 없는 실행 경로를 제공하지 않는다.
- 플러그인은 선언한 token·출력이 요구하는 권한과 정확히 일치해야 하며, package·action·입출력 상한을 넘거나 설치 후 manifest 무결성 검사를 통과하지 못하면 실행 목록에 들어가지 않는다.
- v2 웹 패널 package는 앱 번들 검토본과 identifier+manifest SHA-256 digest가 모두 일치해야 하며, 번역·YouTube·브라우저 capability가 서로의 scope를 대신하지 않는다.
- WebKit 패널은 top-level request/response와 lifecycle 폐기를 재검증하고 script popup·download·upload·media capture·file drop·deprecated TLS를 차단한다. 사용자 클릭인 표준 YouTube 링크만 exact host 확인 뒤 패널 또는 시스템 브라우저로 보낸다. 이 품질 기준을 “모든 subresource 차단”이나 “무추적”으로 표현하지 않는다.

## 9. 결정이 필요한 질문

1. 다음 공개 릴리스에서 변환 작업대를 안정화 기능으로 포함할지, 별도 실험 기능으로 표시할지?
2. 무상 업데이트 기간과 유료 메이저 업그레이드 정책을 어떻게 문장으로 보장할 것인가?
3. 직접 클라우드 연동 우선순위는 iCloud Drive, Google Drive, Dropbox, OneDrive 중 무엇인가?
4. OCR의 최우선 자료는 한국어 전공 교재, 영문 논문, 손글씨 노트, 표·수식 중 무엇인가?
5. 인증서 기반 디지털 서명이 실제 업무에 필요한가, 아니면 우선은 그래픽 서명과 평탄화로 충분한가?
6. 페이지 이미지 기반 Office 내보내기 다음에는 편집 가능한 문단 재흐름과 레이아웃 고정 객체 중 어느 쪽을 우선할 것인가?

이 답은 다음 구현 순서를 바꿀 수 있지만, 현재 MVP를 실행하고 검증하는 데 반드시 필요한 선행 조건은 아니다.
