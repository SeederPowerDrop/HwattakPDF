# 비정상 PDF 글꼴의 드래그 선택 보완 — 2026-09-23

## 원인

제보된 PDF는 일부 글꼴의 `/Ascent`가 67,306,242로 기록되어 있었다. 같은 글꼴의 `/FontBBox` 상단은 816이었다. PDFKit만 사용하는 독립 재현에서도 짧은 문장의 선택 영역이 약 639,412pt로 계산됐다. 회전된 페이지에서는 이 잘못된 높이가 긴 세로 띠로 보이고 여러 선택 영역이 겹쳐 진한 파란색을 만들었다.

직접 원인은 파일의 비정상 글꼴 정보와 PDFKit의 해석이다. 기존 앱은 기본 드래그를 PDFKit에 맡겨 이 경우를 보완하지 못했다. 시험용 사본의 글꼴 정보만 정상화하면 기본 선택 영역도 정상화됨을 확인했다. 사용자 원본과 원문은 소스 저장소에 포함하지 않았다.

## 변경

- 클릭한 페이지에서 최대 24개 문자 선택을 검사한다. 단일 문자의 선택 영역이 페이지 크기의 4배를 넘는 등 비정상인 경우 사각형 영역 선택으로 전환한다. 검사 결과는 최근 4개 페이지만 보관한다.
- 정상 PDF의 기본 드래그는 유지한다. `Option`을 누른 채 드래그하면 어떤 페이지에서든 영역 문자 인식을 사용할 수 있다. 한 번에 현재 페이지의 사각형 영역을 선택한다.
- 지정한 영역만 제한된 크기의 이미지로 만들고 Mac의 Vision으로 인식한다. 원본 파일이나 전체 OCR 기록을 수정하지 않는다. 표시된 주석도 렌더링에 포함해 가려진 원문이 인식되지 않게 한다.
- 인식한 줄과 원래 페이지 좌표를 모델의 선택으로 연결한다. 번역 플러그인, 공유 메모, 선택 영역 AI 문맥, 복사, 주석이 같은 선택을 사용한다. 이 선택을 PDFKit의 내부 선택 객체로 설치하지 않는다.
- 선택 표시는 한 번만 반투명하게 채운다. 회전·확대·스크롤을 반영하고 검색·탭/문서 교체·페이지 이탈·도구 변경·Escape·선택 해제 시 작업과 표시를 취소한다. 취소된 드래그의 나머지 마우스 이벤트도 PDFKit에 넘기지 않는다.
- 복사 권한은 시작 시점과 비동기 결과 적용/복사 시점에 확인한다. 새로운 검색 선택이나 수정된 문서에 오래된 인식 결과를 적용하지 않는다.

## 확인 범위

첨부 실문서에서 한 문구와 여러 줄을 각각 지정해 해당 영역만 로컬에서 인식되는 것을 확인했다. 흰색 가림 주석을 덧댄 시험에서는 가려진 원문이 인식 결과에 포함되지 않았다. 실문서 검사는 임시 작업 공간에서만 수행했다.

자동 검사는 합성 PDF를 사용한다. 비정상 글꼴 감지, 정상 선택 유지, 네 방향 회전과 잘린 페이지의 좌표, 메모리상 회전 변경, 가림 주석 렌더링, 선택 텍스트/AI 출처, 드래그 취소, 검색·페이지·도구 전환과 복사 권한을 다룬다. 기존 스크롤·검색·공유·주석·이미지 편집·양식 입력 검사도 함께 실행했다. macOS 15 PDFKit의 기존 호스트 종료 문제로 제외되는 스크롤 검사 2건은 통과로 집계하지 않는다.

문자 인식은 문장부호·철자·다단 읽기 순서를 틀릴 수 있다. 인식 완료 상태에 확인 안내를 표시한다. 이 보완은 사각형 선택 기능이며 PDF 자체의 글꼴 정보나 전체 문서의 검색 텍스트를 교정하는 기능은 아니다.

## 재제보 후 실제 설치·화면 확인

사용자가 같은 파란 띠를 다시 제보한 뒤 실행 중인 프로세스와 설치 파일을 확인했다. 실행 경로는 `/Applications/HwattakPDF.app`이었고, 해당 설치본에는 영역 선택 문구와 새 실행 파일이 없었다. 앞선 작업은 별도 출력 폴더에 개선판을 만드는 데 그쳤으며 실제 사용 중인 앱에 적용됐는지 확인하지 못했다.

기존 앱을 정상 종료하고 `outputs/region-selection-2026-09-23/HwattakPDF-before-update.app`에 백업한 뒤, `/Applications/HwattakPDF.app`을 개선판으로 교체했다. 설치본과 개선판 실행 파일의 SHA-256 일치 및 코드 서명을 확인하고 설치 경로에서 다시 실행했다. 열려 있던 13개 탭과 현재 페이지가 복원됐다.

실제 macOS 앱 화면의 문제 페이지(파일 283쪽, 인쇄 250쪽)에서 보조키 없이 본문 네 줄을 사각형으로 드래그했다. 페이지 전체로 번지는 띠가 생기지 않고 해당 줄들만 표시됐다. 이어 앱의 메모 공유 준비 창에서 선택한 영역의 인식 텍스트만 전달되는 것을 확인했다. 공유나 외부 번역 요청은 실행하지 않았고, 확인 창을 닫아 문서로 돌아왔다. 이 확인으로 앞서 남겨 둔 실제 설치본의 수동 드래그 검증을 수행했다. OCR의 문장부호 오인식 및 사각형 경계에 걸친 글자가 잘릴 수 있는 한계는 유지된다.

## PDF Expert 비교 후 일반 텍스트 드래그 개선

사각형 OCR만으로는 같은 파일을 일반 텍스트처럼 선택하는 사용감을 충족하지 못한다. 비교 화면은 파일의 38쪽으로 확인했다. 이를 포함해 파일 282·283쪽의 원본 리소스와 콘텐츠 스트림을 한 페이지의 메모리 전용 PDF로 복제하고 비정상 FontDescriptor 치수만 고치면, 세 페이지 모두 추출 원문이 정확히 동일하면서 선택 좌표가 정상화됐다. 페이지별 생성 시간은 해당 로컬 환경에서 약 17–21ms였으며 렌더링 프레임 속도 측정은 아니다.

기본 드래그는 이 보정된 페이지의 PDFKit 텍스트 선택을 이용한다. 드래그 중 글자 경계가 바뀔 때 원래 화면의 선택 표시와 번역·복사에 전달할 선택 내용을 함께 갱신한다. 첫 줄 중간에서 시작해 다음 줄 중간까지 선택하거나 역방향으로 드래그할 수 있다. 두 번 클릭하면 단어를 선택하며, 그 상태의 드래그는 단어 단위로 확장한다. 원본 페이지를 화면이나 문서에서 교체하지 않으며 문서를 수정 상태로 만들지 않는다.

메모리 복제는 원래 폰트 인코딩과 ToUnicode, 콘텐츠 좌표를 보존한다. `PDFPage.dataRepresentation()`으로 재생성할 때 일부 글자가 달라지는 문제가 있어 이 경로를 사용하지 않는다. 원문 비교는 공백·줄바꿈의 연속 길이만 허용하며 글자와 단어 경계가 달라지면 보정을 사용하지 않는다. 최근 네 페이지까지만 보관하고 문서 교체·수정 시 폐기한다. 잠금·복사 권한, 객체 수·깊이·메모리 한도를 확인하며 외부 스트림 파일을 읽지 않는다.

지원하지 않는 구조나 원문 불일치·좌표 이상이 남는 페이지는 기존 사각형 OCR로 돌아간다. Option 드래그도 사각형 OCR로 유지한다. 이번 일반 드래그 보정의 범위는 한 페이지 안이다. 여러 페이지를 넘나드는 연속 선택까지 PDF Expert와 동등하다고 검증한 것은 아니다.
