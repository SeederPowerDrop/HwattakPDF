# 누적 개발 변경과 기록 통합 — 2026-09-13

공개 소스 기준 `1584312` 이후 작업한 변환·안정화·플러그인·기본 PDF 앱 연결 변경을 개발 기록과 함께 묶었다. 사용자 요청에 따른 GitHub 소스 반영이며, **새 앱 릴리스나 기존 0.8.0 배포 ZIP 교체는 아니다.** 소스의 버전 표시는 다음 공개 릴리스 준비 전까지 0.8.0 (build 18)을 유지한다.

## 포함한 변경

- 이미지·HTML 기반 PDF 만들기, Word/PowerPoint 내보내기와 입력·출력 검증
- 자동 복구, 휴면 문서와 세션 수명, 대용량 탭·썸네일 처리 개선
- 필압 필기 추출 충돌, Office 치수 변환, PDF 복사·지우개 권한, OCR 복구 예약, 복구 탭 닫기 문제 수정
- schema 3 문서 명령, 명령 팔레트, 하이라이트·밑줄·태블릿 도구와 예제 플러그인
- 플러그인 제작·보안·호환성·한국어/영어 안내, 패키지 검증 도구와 API 제안 양식
- 설정 화면의 기본 PDF 앱 상태 조회와 Finder 연결 안내, 10개 언어 문구
- 회귀 테스트와 개발·검토·수정 기록

## 공개 범위와 확인한 한계

변경된 소스·문서·예제·테스트를 점검했으며 실제 인증키·개인 경로·사용자 문서, 심볼릭 링크, 10MiB 초과 파일은 발견하지 못했다. `.gitignore`에 따라 `.build/`, `work/`, `outputs/`와 로그·서명키·데이터베이스는 제외한다. 검사 로그와 후보 앱은 로컬에 남기고 요약된 결과만 기록한다.

기존 배포 문서의 Developer ID 미서명·미공증, PDF 주석 기반 편집, 수동 기기 검증 등 한계는 유지한다. 실제 iPad/Sidecar/Wacom, macOS별 GUI와 File Provider, 장시간 실문서 사용, Finder에서 기본 앱 연결을 확정한 뒤 실제 파일 열기는 별도 확인 대상이다. 플러그인은 지원하는 제한된 명령·템플릿·앱 소유 웹 패널 범위이며 임의 JavaScript 플러그인 실행을 지원한다고 주장하지 않는다.

## 소스 반영 전 검증

- macOS 서비스에 접근 가능한 환경에서 `scripts/run_test_batches.sh`의 **59개 클래스·7개 배치·732건** 실행: **730건 통과, 기존 조건부 제외 2건, 실패 0건**.
- 처음 제한 환경에서는 WebKit 프로세스가 종료되어 HTML 관련 4건이 실패했다. 서비스 접근 환경에서 전체 검사를 다시 실행하자 해당 4건을 포함해 모두 통과했다. 환경 실패 로그와 최종 성공 로그를 구분해 보관한다.
- 제외 2건은 기존 macOS 15 PDFKit의 두 페이지 펼침·포인터 중심 확대 테스트다. 이 경로의 macOS 26 검증 job은 기존 GitHub Actions에 유지한다.
- `scripts/validate_project.sh`, `git diff --check` 통과. 변경 문서의 상대 파일 링크를 확인했고 누락된 대상이 없었다.
- 같은 제품 소스로 만든 [기본 PDF 앱 연결 후보](DEFAULT-PDF-APP-2026-09-13.md)의 Release 앱·ZIP·서명·리소스 검사도 완료되어 있다. 이번에는 문서 통합 이후 앱을 다시 배포하거나 기존 Release 자산을 바꾸지 않는다.

로컬 검증 로그는 `work/github-publish-2026-09-13/regression.log`(초기 제한 환경), `regression-native.log`(최종 전체 통과), `static-validation.log`에 저장한다. GitHub에 반영한 commit의 CI 결과는 해당 commit의 Actions 실행에서 별도로 확인한다.
