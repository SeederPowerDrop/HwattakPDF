# 2026-09-05 안정화 결과

대상: HwattakPDF 0.8.0 (build 18)의 로컬 안정화 후보. 기존 개발 중인 이미지/HTML/PDF 조립 및 Office 변환 코드 위에서 감사 결함을 수정하고 안정성·응답성·문서 명령 플러그인을 확장했다. 이 기록은 [수정 전 감사](AUDIT-2026-09-05.md)의 후속이다.

## 수정한 결함

| 문제 | 수정된 동작 | 검증 |
| --- | --- | --- |
| 이미지를 열어 편집한 뒤 임시 PDF를 덮어쓰고 저장 완료로 표시 | 이미지 원본과 렌더링용 PDF를 구분. 최초 PDF 저장은 별도 목적지를 요구. 원본 이미지와 alias를 저장 대상으로 거부 | 미저장 상태 유지, 원본 bytes 보존, 별도 저장 후 휴면/복원 |
| 같은 이미지를 다시 열 때 중복 탭 생성 | 원본 파일 정체성으로 기존 탭을 선택. 같은 요청 안의 중복도 제거 | 중복 요청 후 탭 1개 |
| 페이지 조립에서 선택 뒤 외부 변경된 원본 PDF를 조용히 사용 | 선택 시 파일 버전을 캡처하고 조립·최종 저장 직전에 재확인. 출력과 입력 PDF가 같은 위치인 경우 거부 | 외부 변경 시 오류, 결과 저장 취소 |
| 이미지 세션이 임시 PDF 경로에 의존 | 원본 이미지의 bookmark를 저장하고 필요할 때 미리보기 재생성 | 실제 세션 저장/복원, 임시 backing 삭제 후 재생성 |

파일 버전 검사는 기존 파일 metadata와 위치/alias 정책을 사용한다. metadata를 고의로 보존하는 모든 변경을 검출하는 전체 내용 hash 또는 실시간 협업 merge는 아니다.

## 로딩과 대용량 작업

- 이미지 열기를 취소 가능한 백그라운드 변환으로 이동했다. PDFKit 객체 그래프를 UI와 공유하지 않고 만들어진 파일 URL을 전달한다. 중단된 요청의 미설치 미리보기를 정리한다.
- 썸네일 렌더링을 SwiftUI `body`에서 분리했다. 화면이 먼저 배치된 뒤 35ms 지연을 거치며, 빠른 스크롤로 사라진 셀은 렌더링 전에 취소된다. 기존 크기/개수 제한 캐시와 메모리 압력 해제를 유지한다. 실제 PDFKit 렌더링은 문서 소유 actor에서 수행한다.
- Word/PowerPoint 내보내기는 한 페이지씩 렌더링해 임시 PNG에 쓰고, 이미지 파일을 256 KiB 버퍼로 ZIP에 전달한다. 전체 페이지 이미지와 완성 ZIP을 동시에 메모리에 보유하는 UI 경로를 제거했다. CRC32에는 lookup table을 사용한다.
- 페이지 사이 UI 실행 기회, 진행률, 취소를 제공한다. 내보내기 중 문서가 바뀌면 저장을 중단한다. 완료 ZIP을 별도 파일로 준비하고 목적지가 외부 변경되지 않았는지 확인한 뒤 교체한다. 실패/취소 시 기존 목적지를 유지한다.
- 기존 지연 탭 로딩, 제한된 동시 파일 검사, 비활성 clean 문서 휴면을 대용량 합성 문서로 재검증했다. 내보내기 중인 문서는 휴면 대상에서 제외한다.

### 측정

macOS 15.7.5, arm64, 개발용 Debug 테스트, 로컬 임시 파일. 파일을 생성한 직후의 OS 캐시가 적용될 수 있다. 모든 PC·PDF의 속도나 실제 스크롤 FPS를 보장하는 수치가 아니다.

## 작업 복구

- 설정에서 켜고 끌 수 있는 로컬 자동 복구 사본을 추가했다. 기본 활성 상태이며 암호화되지 않은 문서의 확정된 편집을 대상으로 한다.
- 편집을 멈춘 뒤 5초, 500쪽 초과는 60초 뒤 저장한다. 암호화 PDF와 진행 중인 OCR/Office 내보내기는 제외한다. 예약 후 설정을 꺼도 저장하지 않는 것을 확인했다.
- PDF 세대를 먼저 저장·검증하고 작은 manifest를 원자 교체한다. 실패하면 이전 정상 세대를 보존한다. 원본 PDF는 자동 복구가 덮어쓰지 않는다.
- **PDF → 작업 복구…** 또는 설정에서 복구 목록을 연다. 복구 항목은 독립된 작업용 파일로 열며 별도 PDF 저장을 요구한다. 복구 목록의 기존 기록은 사용자가 삭제할 때까지 남는다.
- 해당 작업의 정상 저장·명시적 버리기와 현재 자동 복구 기록의 수명을 연결했다. 복구 파일은 1개 256 MiB, 등록된 복구 PDF 합계 1 GiB, 기록 32개로 제한한다. 한도/저장 실패는 문서 하단에 표시한다.
- OCR 체크포인트의 로컬 평문 텍스트를 설정에서 지울 수 있다. OCR 작업 lease가 살아 있으면 삭제하지 않으며 디렉터리 정리는 백그라운드에서 한다.

복구는 정상 저장을 대체하지 않는다. 아직 확정하지 않은 입력, 마지막 유휴 시간 이후 편집, 암호화 문서는 복구되지 않을 수 있다. PDFKit 직렬화 자체는 문서 소유 actor에서 실행되므로 매우 큰/복잡한 문서의 복구 저장 순간 지연은 남아 있다. 강제 종료로 manifest 게시 전 남은 orphan 파일의 자동 만료 정책도 후속 개선 대상이다.

## 플러그인과 태블릿

schema 3은 `annotationWrite`·`toolControl`·`workspaceNavigation` 권한으로 하이라이트, 밑줄, 펜 설정, 지우개/선택, 모드/페이지 이동을 제공한다. 기존 설치·업데이트·비활성화·변조 검출과 함께 `⇧⌘P` 검색형 명령 팔레트를 추가했다. 주석 명령은 실제 문서 권한·선택 객체 소유권을 재검사하고 기존 Undo/Redo를 사용한다. 패키지가 원본 파일을 직접 저장하지 않는다.

기본 검토 패키지에 Study Markup, Tablet Tools, Reading Navigation을 추가했다. 기존 번역·웹 브라우저와 합쳐 다섯 개이며 사용자가 검토 후 설치한다. 모든 새 공통 UI 문자열은 기존 10개 언어에 추가했다. 예제 패키지 자체의 이름과 명령 제목은 영어다.

Sidecar 또는 태블릿이 전달하는 tablet-point/pressure 이벤트를 처리한다. 가변 굵기 획은 표준 PDF Stamp appearance로 저장하고 긴 획의 점 개수를 제한한다. 필압 차이가 저장 후 재개방된 PDF의 실제 픽셀에도 유지되고 Undo/Redo가 작동하는 것을 검증했다. 실제 iPad/Wacom 입력 지연·필압·팜 리젝션과 네트워크 펜 전송은 검증/구현 완료 범위에 포함하지 않는다.

제작 예제·정확한 명령과 범위는 [문서 명령 API 가이드](PLUGIN-HOST-API.md)에 있다. Obsidian JavaScript 플러그인을 그대로 실행하는 호환 런타임이나 온라인 플러그인 마켓은 아직 없다.
