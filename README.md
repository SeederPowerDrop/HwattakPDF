# HwattakPDF

구독과 계정 없이도 내 Mac에서 핵심 기능이 동작하는 네이티브 PDF 학습·편집기 프로토타입입니다. 읽기·편집·OCR은 로컬 우선이며, 외부 AI는 사용자가 직접 API 키를 연결하고 요청별 전송 내용을 확인한 경우에만 사용합니다.

현재 공개 버전은 **0.8.0 (build 18)**입니다.

> 현재 다음 릴리스용 소스 트리에는 아래에 설명한 이미지·HTML 기반 PDF 만들기와 Word/PowerPoint 내보내기가 포함되어 있지만, 이 기능은 공개 0.8.0 태그·배포 ZIP에는 들어 있지 않습니다. 다음 릴리스 전에 새 버전·체크섬과 Office 앱 수동 호환성 검증 결과를 확정합니다.

공식 저장소: [github.com/SeederPowerDrop/HwattakPDF](https://github.com/SeederPowerDrop/HwattakPDF)

> 2026-09-05: 이미지 저장·중복 탭·조립 원본 변경 버그를 수정하고, 취소 가능한 Office 내보내기·로컬 작업 복구·필압 획·문서 명령 플러그인을 추가했습니다. 검증 범위와 한계는 [안정화 기록](Documentation/STABILIZATION-2026-09-05.md)에 있습니다.

## 현재 구현

### 세 가지 작업 모드

각 PDF 탭은 목적에 맞는 도구만 보이도록 모드를 나누며, `⌃1`·`⌃2`·`⌃3`으로 빠르게 전환할 수 있습니다. 모드 전환은 PDF 바이트를 바꾸지 않고 탭의 세션 상태로 복원됩니다.

툴바는 두 단으로 정리했습니다. 첫 줄의 `보기 · 편집 · 학습`, 페이지 이동·저장·화면 배치·검색은 자리를 유지하고, 둘째 줄에는 현재 모드에서 쓸 수 있는 도구만 나타납니다. 학습 AI 빠른 작업은 하나의 메뉴로 묶어 기능은 유지하면서 화면의 밀도를 낮췄습니다.

모드 도구줄은 제목 없이 가운데 정렬되며 접어 PDF 영역을 넓힐 수 있습니다. `집중 보기`는 탭·툴바·사이드바·상태표시줄·AI 패널을 임시로 감추고 PDF만 표시하며, 상세 배치와 패널 위치는 macOS `보기` 메뉴에서 조정합니다.

| 모드 | 단축키 | 집중하는 작업 |
| --- | --- | --- |
| 뷰어 | `⌃1` | 읽기·선택·복사/붙여넣기, 주석 메모, 그래픽 서명, 번역·PDF AI, 선택문에 메모를 덧붙여 공유 |
| 에디팅 | `⌃2` | PDF 위 인라인 자유 텍스트, 이미지·서명 이미지 삽입, 그래픽 서명과 펜 필기, 페이지 재정렬·회전·삭제·병합·추출 |
| 학습 | `⌃3` | 번역·용어 설명·요약·풀이 과정·학습 포인트·퀴즈, 타이핑/펜 메모, 색상·두께·진하기를 조절하는 하이라이트/밑줄, 메모 공유 |

뷰어/학습의 메모 공유는 선택한 내용 최대 4,000자와 사용자가 쓴 메모 최대 8,000자를 일반 텍스트로 복사하거나 macOS 공유 시트에 넘깁니다. PDF 전체, 파일 경로, 선택하지 않은 숨은 텍스트는 포함하지 않으며 공유 버튼을 누르기 전에는 외부로 보내지 않습니다.

- PDFKit 기반 1페이지 연속 보기, 2페이지 연속·한 펼침 고정 보기와 1~12페이지 지연 렌더링 개요
- 툴바의 1페이지·연속 양면·고정 양면·4페이지 즉시 버튼과 macOS `보기` 메뉴의 2×2/1×4·이동 방향·3~12페이지 사용자 지정 보기, 현재/전체 페이지 번호 입력 이동, 스크롤 현재 페이지 HUD
- 1·2페이지 PDFKit 보기와 3~12페이지 개요에서 기본 `⌥+스크롤` 확대·축소, `⇧+세로 휠` 가로 이동, 기존 세로·가로 스크롤과 핀치 확대 유지. 확대 키는 설정에서 `⌥`·`⌘`·끔 중 선택하며 PDFKit 본문은 포인터 위치를 중심으로 확대
- 썸네일 페이지 패널의 왼쪽·오른쪽·상단·하단 배치, 구분선 드래그 폭·높이 조절, 1장·책 펼침 2장·4장 묶음 보기, 트랙패드·슬라이더 썸네일 크기 조절
- 여러 PDF를 독립된 탭으로 열기, 전체 파일명 호버 표시, 좌우 드래그 재정렬, 중복 파일 탭 방지와 미저장 변경 보호
- **[미출시 개발 트리]** JPEG·PNG·TIFF·HEIC·HEIF·GIF·BMP·WebP 이미지를 PDF와 같은 탭 뷰어에서 열기. 전용 PDF 만들기 화면에서 여러 이미지·로컬 HTML·다른 PDF의 선택 페이지만 가져와 순서를 바꾸고, A4 공백 페이지를 끼운 뒤 하나의 PDF로 저장하고 페이지 수를 다시 확인
- 탭을 다른 탭 중앙에 드롭하면 즉시 생성되고 기존 스택에도 합류하는 2단 탭 스택, 가장자리 드롭 재정렬, 이름 변경·접기·펼치기, 상단 탭 분리와 새 창 tear-out
- 탭이 사용 폭을 넘으면 우측에 고정되는 이전·다음·추가 버튼과, 여유가 있을 때 마지막 탭 뒤에 붙는 추가 버튼
- 탭·탭 스택·활성 PDF 상태를 주제별로 분리하는 워크스페이스 생성·전환·이름 변경·삭제·탭 이동
- security-scoped bookmark로 열린 파일·워크스페이스·탭 순서·스택·활성 페이지를 저장하고 다음 실행에서 지연 복원
- 활성 탭만 `PDFView`를 유지하고, 기본 3개 resident 문서 예산·LRU 휴면·macOS 메모리 압력 대응으로 많은 대용량 PDF 탭 관리
- HwattakPDF 프로세스의 실제 CPU·상주 메모리와 파일 크기·페이지 수 기반 PDF 탭별 예상 부담을 구분해 보여 주는 리소스 모니터
- 보안 북마크로 최근 PDF를 최대 7개 기억하고 시작 화면에서 다시 열기·개별 제거·목록 비우기
- 열린 PDF 중 2~4개를 좌우 또는 위아래로 배치해 비교하고, 비율 기반 스크롤 동기화와 문서별 잠금 사용
- 썸네일 다중 선택, 드래그/버튼 재정렬, 삭제, 회전, 추출, 병합
- 문서별 최대 22단계 `⌘Z` 실행 취소와 `⇧⌘Z` 다시 실행: 펜·하이라이트·텍스트·서명·이미지·양식·페이지 편집을 전체 PDF 복사본 없이 변경분으로 기록
- Finder에서 PDF를 탭 막대뿐 아니라 PDF 본문·페이지/검색/AI 사이드바·빈 화면을 포함한 문서 작업공간 어디에나 드롭해 각각 독립 탭으로 열고, 이미지는 현재 페이지에 추가
- 다중 페이지 개요의 페이지 카드도 직접 드래그하여 재정렬
- `⌘F` 전체 문서 검색, 페이지별 문맥·일치 개수를 보여 주는 검색 사이드바, 결과 클릭·Enter/Shift+Enter 순환 이동, 한국어·영어·일본어·중국어·아랍어 Unicode 정규화 검색
- 표준 PDF 하이라이트·자유 텍스트·잉크 주석과 추가한 텍스트의 선택·이동, 에디팅 모드에서 페이지를 클릭해 글꼴·크기·색상·정렬·배경을 조절하는 인라인 자유 텍스트 편집
- 위조 가능한 PDF marker를 편집 권한으로 믿지 않고, 뷰어·학습 모드의 이동·삭제를 현재 실행에서 생성하거나 명시 편집한 주석으로 제한. 저장 후 재개방·휴면한 표식 주석의 넓은 편집은 에디팅 모드에서 수행
- 이미지 추가, 선택·이동·크기 조절·자르기·삭제와 이미지 간 레이어 순서 변경
- 선택 페이지 PNG 추출
- **[미출시 개발 트리]** 현재 PDF의 페이지별 보이는 모양을 우선 보존해 Word(.docx) 또는 PowerPoint(.pptx) 문서로 로컬 변환
- 버튼으로 시작하는 한 손가락 트랙패드/마우스 서명, 감도·스무딩·굵기·속도 영향 세부 설정, 배치 후 선택·이동·크기 조절, 현재 사용자 Keychain 기반 기본 서명 자동 저장·교체·삭제
- Apple Vision 기반 한·영·일 로컬 OCR, 페이지별 증분 체크포인트와 중단/재개
- **[미출시 개발 트리]** PDF 만들기 과정에서 `안정성 우선`(240 DPI 정확 OCR·긴 HTML 준비 대기)과 `속도 우선`(160 DPI 빠른 OCR·이미지 축소·HTML 준비 대기 단축)을 선택하고, 두 방식의 예상 시간 범위와 예상 출력 용량을 미리 비교
- **[미출시 개발 트리]** 선택한 방식으로 한·영·일 OCR을 실행해 검색 가능한 텍스트 층을 추가하고, 인식 문자열을 클립보드 또는 UTF-8 텍스트 파일로 별도 추출. 완료 후 실제 소요 시간과 파일 크기도 표시
- 보이지 않는 텍스트 레이어가 포함된 검색 가능 PDF 내보내기
- OpenAI·Claude·Gemini·DeepSeek·Qwen·사용자 지정 API를 연결하는 탭별 PDF AI 패널, 명시적 전송 미리보기와 Keychain API 키 보관
- 선택/현재/선택 페이지/대표 문서 문맥의 요약·분석·수학/과학 풀이·채우기 초안, 로컬 관련 PDF 검색, OpenAI 웹 출처와 호출별 승인형 원격 MCP
- 권한을 검토한 `.hwattakplugin` 설치·업데이트·비활성화·삭제와 플러그인 메뉴 액션. schema 1(v1) 선언형 텍스트 액션의 호환성을 유지하고, schema 2는 패키지 코드를 실행하지 않은 채 앱 소유 번역·웹 브라우저 패널을 분리된 권한으로 제공. YouTube 패널 지원 코드는 정책·동의 UI를 마칠 때까지 비활성 실험 경계로 유지
- iCloud Drive와 Finder File Provider를 포함한 시스템 열기/저장 패널
- 같은 폴더의 검증된 임시 PDF 교체를 우선하는 저장(파일 단위 샌드박스 권한에서는 사전 직렬화·사후 재열기 검증을 거친 직접 쓰기 호환 경로)
- 같은 원본에 덮어쓰기 직전 외부 변경을 검사하고, 충돌 시 외부 파일과 앱의 미저장 편집을 모두 보존한 채 복사본 저장으로 복구
- 저장하지 않은 탭을 닫거나 창·앱을 종료할 때 문서별 저장 여부 확인
- 최신 앱 아이콘의 남색·상아·코랄을 반영한 라이트·다크 적응형 작업공간 UI
- 제작 배경·GitHub·후원 링크와 사용자 제공 그림을 담은 2000년대 Windows풍 `HwattakPDF 정보` 창
- 도움말 메뉴의 `HwattakPDF 사용법` 창에서 기능·아이콘·단축키를 10개 주제로 탐색하고 검색

### 기본 웹 패널 플러그인

0.8.0 (build 18) 앱 번들에는 `번역 도우미`, `웹 브라우저`, `Study Markup`, `Tablet Tools`, `Reading Navigation` 다섯 가지 기본 플러그인의 검토본이 들어 있습니다. 자동으로 설치·활성화되지는 않습니다. `플러그인 > 플러그인 관리…`를 열고 `HwattakPDF 기본 플러그인`에서 각 항목의 권한을 확인한 뒤 `검토 및 설치`를 누르세요. 설치 목록은 검색할 수 있고, 각 행의 톱니바퀴에서 활성 상태·권한·제공 작업·정보와 기본 플러그인 전용 옵션을 관리합니다. 번역·브라우저는 PDF 오른쪽 패널로 열립니다. 문서 명령 플러그인은 하이라이트·밑줄·펜 설정·페이지 이동을 제공하며 `⇧⌘P` 팔레트에서 검색할 수 있습니다. [직접 플러그인 만들기와 태블릿 필기](Documentation/PLUGIN-HOST-API.md)를 참고하세요.

- `번역 도우미`: 선택문 또는 현재 페이지의 제한된 텍스트를 편집·확인한 뒤 Google 번역, ChatGPT 또는 Claude와 사용합니다. 기본 서비스·대상 언어·원문 펼침 상태를 설정할 수 있습니다.
- `웹 브라우저`: 공개 HTTPS 사이트를 여는 임시 패널입니다. 기본 검색 엔진과 시작 페이지 자동 로드를 설정할 수 있으며, PDF 텍스트·파일·문서 객체를 페이지에 전달하는 bridge는 없습니다.

`Examples/Plugins/YouTubeStudy.hwattakplugin`은 보안 검토를 위한 소스 전용 예제이며 관련 호스트 지원 코드는 0.8.0 실행 파일에서 활성화할 검토본 없이 대기합니다. YouTube가 요구하는 앱 개인정보처리방침·이용약관·사전 동의와 상시 정책 링크를 완성하기 전에는 해당 manifest를 앱 번들에 넣지 않으며, 공식 기본 플러그인으로 설치할 수 없습니다.


플러그인 제작자는 [처음 만드는 가이드](Documentation/PLUGIN-DEVELOPMENT.md), [English quick start](Documentation/PLUGIN-DEVELOPMENT.en.md), [호환성·API 확장 제안](Documentation/PLUGIN-COMPATIBILITY.md), [보안 가이드](Documentation/PLUGIN-SECURITY.md)에서 시작할 수 있습니다. 복사 가능한 커뮤니티 예제와 실제 호스트 검사기를 사용하는 `scripts/validate_plugin.sh`를 제공합니다.

## 실행

Xcode 26.3 및 macOS 14 이상:

SwiftPM 타깃과 실행 파일은 기존 빌드 호환성을 위해 내부 이름 `VibePDF`를 유지합니다.

```bash
swift run VibePDF
```

PDF 경로를 인자로 바로 열 수도 있습니다. 여러 경로를 넘기면 각 PDF를 독립된 탭으로 엽니다.

```bash
swift run VibePDF -- /path/to/first.pdf /path/to/second.pdf
```

`swift run VibePDF`는 소스 target만 직접 실행하는 개발 경로라
`Examples/Plugins`의 배포용 기본 플러그인 2개를 앱 resource로 묶지 않는다. 번역 도우미와
웹 브라우저의 `플러그인 관리 > HwattakPDF 기본 플러그인` 설치 흐름까지
확인하려면 아래 앱 번들 빌드를 사용한다.

앱 번들 생성:

```bash
./scripts/build_app.sh
```

현재 `Info.plist`가 공개 버전 0.8.0 (build 18)을 유지하고 있으므로, 미출시 변경이 있는 다음 릴리스용 소스 트리에서 스크립트를 실행해도 파일명은 `outputs/HwattakPDF-0.8.0-macOS-arm64.zip`으로 생성됩니다. 이 산출물은 기존 공개 0.8.0과 내용·체크섬이 다르므로 릴리스 자산으로 업로드하면 안 됩니다. 다음 배포 전 버전과 build를 먼저 올리고 새 검증 기록을 만드세요.

결과는 `outputs/HwattakPDF.app`과 Apple Silicon용 ZIP입니다. 현재 번들은 개발용 ad-hoc 서명이며 Apple 공증을 받지 않습니다. `LICENSE`, `NOTICE`, 자산·표장 고지는 앱의 `Contents/Resources/Legal`에도 함께 포함됩니다.

## 기본 PDF 앱 연결 (미출시 개발 트리)

설치한 `HwattakPDF.app`을 응용 프로그램 폴더에 두고 실행한 다음, **HwattakPDF > 설정… (⌘,) > 기본 PDF 앱**에서 **Finder에서 연결 설정…**을 누릅니다. Finder에서 선택된 설정용 PDF의 **정보 가져오기 (⌘I) > 다음으로 열기 > HwattakPDF > 모두 변경**으로 연결을 확정합니다. 목록에 앱이 없다면 **기타…**에서 설치한 앱을 선택하세요. 앱으로 돌아오면 실제 기본 연결 상태를 다시 확인합니다.

이 기능은 앱 전용 설정용 PDF를 사용하며 개인 문서를 수정하지 않습니다. 현재 샌드박스 배포 앱은 macOS의 기본 연결을 직접 변경할 수 없어 Finder에서 마무리합니다. 개별 PDF에 별도 연결을 지정했다면 해당 파일의 정보 가져오기에서도 확인하세요. `swift run` 실행 파일에서는 설정 버튼을 사용할 수 없습니다. 구현과 검증 범위는 [연결 설정 개발 기록](Documentation/DEFAULT-PDF-APP-2026-09-13.md)에 정리했습니다.

## 중요한 경계

에디팅 모드의 인라인 텍스트와 “시각적 텍스트 교체”는 PDF 표준 FreeText 주석을 페이지 위에 올리는 오버레이입니다. PDF 콘텐츠 스트림의 원문을 직접 수정하거나 삭제하지 않으므로 가린 원문이 검색·복사·접근성 추출에 남을 수 있으며, **보안 삭제나 secure redaction이 아닙니다**. 이미지도 새 스탬프 주석으로 추가합니다. 기존 콘텐츠 스트림의 폰트 subset·문단 reflow·Image XObject 자체 편집, 보안 redaction, 인증서 기반 PAdES 전자서명은 별도 고급 PDF 엔진이 필요한 후속 범위입니다.

학습 모드의 색상·두께·진하기 조절형 하이라이트/밑줄은 PDFKit이 표준 Highlight/Underline의 투명도를 안정적으로 재저장하지 못하는 한계를 피하려고 외형을 구운 표준 Stamp로 저장합니다. 다른 뷰어에서 **보이는 결과를 보존**하기 위한 방식이며, 의미론적 Highlight/Underline 주석이나 재개방 후 앱 전용 학습 표식 편집 모델은 아닙니다.

Mac에서의 펜 입력은 마우스·트랙패드 또는 Sidecar가 전달한 Apple Pencil 포인터 이벤트를 사용합니다. Apple Pencil을 Mac 앱에 직접 연결하거나 압력·기울기를 네이티브 PencilKit으로 받는 기능은 아닙니다.

OCR 출력은 보이는 페이지와 주석을 평탄화한 새 PDF입니다. 링크·폼·댓글·기존 전자서명의 상호작용을 유지하지 않으므로 원본도 보관해야 합니다. iPhone/iPad 원격 서명, 직접 OAuth 클라우드 브라우저, 외부 Local AI 모델 다운로드/선택도 현재 앱이 아닌 다음 단계입니다.

이미지 보기와 PDF 만들기는 파일당 64 MiB·원본 1억 2천만 픽셀을 넘는 입력을 거부하고 첫 번째로 decode 가능한 프레임만 사용합니다. 따라서 애니메이션 GIF나 다중 페이지 TIFF/HEIF의 전체 프레임을 PDF 페이지로 펼치는 기능은 아닙니다.

Word·PowerPoint 변환은 네트워크 전송 없이 각 PDF 페이지를 고해상도 이미지로 문서에 배치해 페이지별 보이는 모양을 담습니다. 실제 Office 앱과 버전별 시각 호환성은 다음 릴리스 전 수동 확인 항목입니다. 변환된 문서에서 원문 문단·표·도형을 개별 객체로 다시 편집하거나 텍스트를 재배치하는 변환은 아닙니다.

HTML 변환은 비영구 WebKit 세션에서 같은 폴더 아래의 CSS·이미지·글꼴과 스크립트를 불러와 A4 페이지로 나눕니다. 현재 PDF 만들기 화면은 HTTP·HTTPS 원격 자원을 차단하도록 구성했지만 완전한 네트워크 방화벽을 보증하지 않으며, 외부 서버에만 있는 스타일이나 이미지는 결과에 포함되지 않을 수 있습니다. 로컬 HTML의 JavaScript는 이 세션 안에서 실행되고 원본 폴더 아래 파일에 접근할 수 있으므로 출처를 신뢰할 수 없는 HTML은 변환하지 마세요. 이는 별도 프로세스 보안 격리나 HTML 무해화 기능이 아닙니다. 예상 시간과 용량은 입력 메타데이터 기반 범위이며 Mac 성능, 이미지 압축률, HTML 레이아웃과 OCR 글자 밀도에 따라 실제 값이 범위를 벗어날 수 있습니다.

PDF AI와 학습 모드의 AI 빠른 작업은 먼저 공급자와 개발자 API 키를 설정해야 합니다. 선택한 범위의 제한된 텍스트·대화·endpoint를 미리 보여 주고 사용자가 요청별로 명시적으로 동의한 뒤에만 외부 공급자로 전송하며, 원본 PDF 파일을 자동 업로드하지 않습니다. API 키는 현재 사용자의 비동기화 Keychain에 저장하고, 공식 공급자 키는 고정된 공식 endpoint에만 전송합니다. AI 답변은 자동으로 PDF를 바꾸지 않으며 채우기 초안도 확인·편집 후 자유 텍스트 주석으로만 추가됩니다. 공급자별 기능, MCP 승인과 개인정보 경계는 [Documentation/AI-INTEGRATION.md](Documentation/AI-INTEGRATION.md)에 있습니다.

플러그인 API schema 1(v1)은 실행형 확장 환경이 아니라 선언형 텍스트 액션이다. v1 패키지는 셸·Keychain·원본 PDF 바이트·직접 네트워크·GPU에 접근할 수 없고, `openURL`은 대상과 포함 데이터 종류를 매번 확인한 뒤 기본 브라우저로만 연다. 설치 화면과 `installation.json`의 SHA-256은 `manifest.json` 변경 감지용일 뿐 **게시자 인증이나 서명이 아니다**. 신뢰할 수 있는 출처의 v1 패키지만 설치해야 한다.

Schema 2도 패키지에 포함된 코드나 HTML을 실행하지 않는다. 매니페스트는 앱이 구현한 패널만 요청하며, 웹 패널을 가진 패키지와 `dev.hwattakpdf.` 공식 식별자 영역을 주장하는 모든 패키지는 검토 UI 전부터 현재 앱 번들 검토본과 `identifier` 및 `manifest.json` SHA-256 digest가 모두 정확히 일치할 때만 설치·로드된다. 번역·일반 브라우저 권한은 서로 대체할 수 없다. 웹 화면은 별도 `WKWebView`의 비영구 데이터 저장소를 사용하고, 공개 HTTPS 상위 이동을 다시 검사하며 script popup·download·upload·카메라/마이크·파일 drag-and-drop·폐기된 TLS를 차단한다. 그러나 이는 완전한 네트워크 방화벽이 아니다. 패널이 열린 동안 원격 페이지의 JavaScript, 메모리 내 쿠키·저장소, 추적 및 하위 리소스 요청은 가능하다. 문서 교체·revision 변경, 탭/앱 비활성화, 집중 보기, 플러그인 비활성화·업데이트·제거 또는 패널 닫기 때 요청과 WebView를 폐기한다. 번역 서비스별 실제 전송, YouTube 미배포 실험 경계와 남은 위험은 [플러그인 가이드](Documentation/PLUGINS.md)에 있다.

기본 서명은 현재 로그인 사용자의 비동기화 Keychain에 저장됩니다. 현재 `build_app.sh` 산출물은 개발용 ad-hoc 서명이므로 로그인 Keychain 호환 경로를 사용하며, `WhenUnlockedThisDeviceOnly`와 앱 업데이트 사이의 안정적인 전용 access group까지 보장하려면 Developer ID 또는 App Store 프로비저닝 서명이 필요합니다.

현재 워크스페이스와 탭은 창별 `MultiDocumentWorkspaceState`에서 여러 `PDFWorkspaceState`를 관리합니다. 열린 파일, 탭 스택, 워크스페이스, 분리 창 구성, 비교 배치와 가벼운 보기 상태는 보안 북마크로 재실행 후 복원하지만, 미저장 PDF 바이트를 별도 복구 저널에 자동 저장하지는 않습니다. 공개 SwiftUI 복원 API의 한계 때문에 분리 창의 소속과 개수는 복원해도 화면상의 정확한 위치·크기는 복원하지 않습니다. PDF 비교는 여러 문서를 나란히 읽고 스크롤 위치를 맞추는 보기 기능이며, 본문 차이를 계산하거나 변경 부분을 자동 강조하는 diff 기능은 아닙니다.

모든 PDF 탭은 하나의 앱 프로세스를 공유하므로 운영 체제가 제공하는 CPU·RSS를 파일별로 정확히 분리할 수 없습니다. 리소스 모니터의 앱 전체 값은 실측이며, PDF별 값은 파일 크기와 페이지 수를 이용한 상대적 **예상 메모리 부담**입니다. 비활성 clean 탭은 resident 예산과 메모리 압력에 따라 휴면하지만, 미저장 편집·진행 중 OCR·동시 비교 문서는 메모리에 고정됩니다. 상세 정책은 [Documentation/LARGE-PDF-PERFORMANCE.md](Documentation/LARGE-PDF-PERFORMANCE.md)에 있습니다.

실행 취소 이력은 문서마다 메모리에만 유지하며 앱을 다시 실행할 때 복원하지 않습니다. 일반 편집은 변경된 주석·좌표·값만 보관하고, 삭제·병합 페이지를 참조하는 구조 작업은 64페이지 비용 상한을 추가로 적용합니다. 저장된 clean 탭이 메모리 절약을 위해 휴면하면 해당 탭의 이력을 비워 PDFKit 객체 그래프도 함께 해제합니다.

문서 검색은 PDF에 포함된 텍스트 층을 대상으로 하며 대소문자·발음 구별 부호·전각/반각·연속 공백과 줄바꿈 하이픈을 정규화합니다. 간체↔번체 번역, 형태소·동의어·의미 검색은 수행하지 않습니다. 텍스트 층이 전혀 없는 스캔 PDF는 지원 언어의 로컬 OCR로 검색 가능한 사본을 만든 뒤 다시 열어야 하며, 현재 내장 OCR 언어 선택은 한국어·영어·일본어입니다. 검색 계산은 페이지 단위로 취소 가능하게 수행하고 결과가 매우 많으면 최대 20,000개까지만 표시합니다.
